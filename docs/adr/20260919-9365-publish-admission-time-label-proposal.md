# 仅出版新闻准入时间标注修订提案

> Status: accepted for proposal publication only · 2026-09-19

## 背景与授权

用户要求 prefilter precision、recall 均 >90%。C6–C8 续轮仍未达标；对第三批回归的 11 条错误查原始 API，6 条 FP 中 3 条已有同来源、同规范 URL 收录记录，只因位于 ±12h 外而标负。原件及边界见[状态](../evaluations/news-admission/status.md)。这说明旧标签同时度量时间对齐，不能把所有 FP 解释为编辑准入错误。

用户在时间口径提问中选择“修订时间标注设计”。该选项明确：先设计原文发布时间、Radar 抓取时间、AIHOT 发现时间的处理；零模型调用、不立即改 gold，设计经确认后再建新 benchmark。旧题库与成绩保留，双 >90% 目标、模型与预算不变。

## 决定与备选

仅出版[待审设计](../evaluations/news-admission/time-label-design.md)：以冻结参照批次中的已观察收录定义拟议 member，C 只约束证据冻结截止，H 才是已有证明的共同覆盖右界。主集正负例适用同一标签盲资格；覆盖不足的未匹配项仍为未知。

不采用仅把 ±12h 改成 48/72h：它仍依赖混用的时间，抓取时补填的发布时间也不会因此变真。不只修 3 条已见错例、不只补正例：这会选择性修标签并改变主集分布。不把全部未匹配项直接判负，也不以只有正例的集合验收 precision。

本决定不 supersede 旧 v1 契约、CLAUDE.md 或 bc72/c31a/d62b 的旧实验边界；未来改变标签语义另待用户确认。若获批，按消费者语义变化建立新 benchmark，而非把旧成绩改名搬过去。

## 审查与未验证项

独立只读 decision-review（`admission_time_design_review`）七项成立，无 blocker、应修或未消解项；唯一提示已纳入：不能把覆盖到 H 的缺席写成“截至 C 瞬时未收录”。审查依据包括用户原始选择、11 条错误原件及时间处理实现；它只放行出版草案。

新主集规模、来源历史深度、真实日期缺失比例、迟到分布与新分数均未验证，属于用户批准设计后的实施工作。本轮本地文档可逆（A0），无生产、题库或运行行为变更；不新增判官、付费批次或采集等待机制。
