# 持续保留过滤前输入，并补收仍可验证的 AIHOT 缺窗

Status: accepted（采集配置后续已获批准启用；评分/判官未授权）

Date: 2026-09-15

## 背景与授权

用户明确排除旧实验 T5，要求同期 Radar 过滤前候选全集与 AIHOT 页面参照，并要求持续收集完整、不受污染的数据。2026-09-15 用户进一步批准本地采集层实现、定向测试与运维文档，选择「滚动 30 天＋冻结集保留」；并未批准评分/判官实施、生产启用或立即删除数据。

现场 daily cron 仍存在。9/14 日志因已有窗口重叠而主动跳过；9/15 日志因 ReadTimeout 失败。Radar 持续 fetch，但业务库 upsert 覆盖旧版本，不能证明历史候选全集。旧 T5 不作为新原始数据，也不删除历史实验文件。

## 决定

在既有 fetch/apply 路径、upsert 之前可选留档完整 FetchedItem（微信正文补全之后），默认关闭。每轮保存 `data/raw-capture/runs/<run-id>/manifest.json` 与 `items.jsonl.gz`；记录代码实态、来源配置摘要、计划来源、时段、逐源状态及文件哈希，不保存凭据配置明文。started 与 completed 分开，失败、304、成功空集合不可混同。

304 只引用与本次条件请求 ETag/Last-Modified 身份一致的成功 payload；没有对应已归档版本时，在原计划 GET 发出前去掉条件头，取得完整 200。归档失败显式失败，不伪装完整。窗口连续性审计需要调用方提供 expected cadence、窗口及启用起点；只有已观察 run 时不宣称调度连续。

30 天保留最近窗口的根及其 payload 依赖闭包，依赖可能早于 30 天。冻结独立保存全部依赖。清理只能作用于明确解析的候选，不因这个决定立即删除任何数据。

AIHOT 保留 capture_v1/item_v1/window_v1 的既有语义，新增 window_v2 支持 API 仍覆盖的缺失完整 UTC 日；目标日必须在相邻两 pass 具有相同 ID 集合、完整分页、真实 SSR tags 及可重放原始绑定。历史窗口不原地覆盖。网络超时/连接失败在原限流和有限重试预算内重试，不重试 WAF/认证拒绝。新补缺模式 opt-in；本地 main 整合本身不得启用新模式。

## 备选与作用域

仅提高 cron 频次不能解决超时直接退出与 upsert 覆盖；定期复制业务 DB 不能还原两轮间版本且体积更大；另建 fetch stack 不是实际输入；原地放宽 v1 破坏历史验证语义；无限保留不符合用户已选 30 天策略。因此使用真实入口旁路留档与版本化补窗。

「完整」仅指给定来源启用/调度契约下系统实际取得的候选全集，不意味着源站历史发布全集。过去没有 raw 的 Radar 窗口不能据新机制追补为完整。最初 T5、现有不完整历史池及评分/判官均不进入本次实施。

## 历史交界与审查

保持 ADR-060/061 的版本冻结及 clean provenance、ADR-047 原源抓取、20260913-c7d4 数据发布边界与 20260914-2307 的 30 天原则；对 20260915-0eeb 仅增加本轮已获批的采集层范围，不授权评测实现。冻结依赖保留不能沿用旧脚本「保留 window 但删除依赖 capture」的限制。

decision-review L1：独立 agent `capture_decision_review`，基线 `901875736f5e5f5339da5eca521d31877ba040fd`。首轮要求补 304 身份、保留依赖闭包、未启动槽三项；两问复核后七项成立，放行本地实现。没有额外非功能加码或基线独立 finding。

尚未验证：实现、反例测试、v2 实采、真实归档体积与生产 cron 消费路径。启用前必须交付这些读数和明确配置差异，不能把本决定当部署验收。
