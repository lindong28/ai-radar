# 20260916-e3a8：采集独立于 AI 处理，事务性 outbox 交接

- Status: accepted（本地实现；生产启用须单独批准）
- Date: 2026-09-16
- Decision review: 独立 Codex 首轮要求修正游标发布间隙及预检/告警交界；补正后两问复核放行。

## Context

用户在询问后端根治「整个 pipeline 共用一把锁，后续处理未结束时，下一轮连 fetch 一起跳过」后，明确要求「现在就执行以上解法」。9/15 23:15 与 23:45 的本机 pipeline 日志均在五次 lock busy 后 SKIP。已有 raw 归档虽在 upsert/过滤之前，仍在同一大锁内。目标是后处理繁忙时继续取得过滤前输入，不是保证源站历史全集或宣称已有七天完整评测集。

## Options Considered

- 移除大锁：会放开主库并发业务写者，违反现有写入互斥边界。
- 仅把 fetch 挪到锁前：fetch 仍写主库 source runtime、正文与头像缓存，仍会被主库写事务阻塞。
- 每轮复制主库：为复用少量采集状态复制全库，带来不必要的周期 I/O。
- 新造抓取器：重复维护已适配的 RSS、网页、X 与微信抓取逻辑。
- 独立采集状态库和事务性 outbox：复用原抓取器，隔离主库写锁，明确可靠交接；采用此项。

## Decision

1. 默认仍走旧 pipeline。显式启用后，独立 collector 调度只抓取、保存不可变 raw 并写采集库，不运行 AI；处理 pipeline 在原 `.pipeline.flock` 下导入队列再执行原 AI 阶段。采集另有自己的互斥锁，不与主锁竞争。
2. 采集库复用原 schema 与解析器，首次只读接入主库的 source 游标和微信正文/头像缓存，不复制评测结果。逐源 outbox 保存 gzip 压缩的过滤前 `FetchedItem`、该次 source runtime 与头像快照；与采集库 items/游标同事务提交。队列身份绑定目标库，消费者不接任意历史实验。
3. 业务队列按单源提交，不以整轮 raw 完成作为唯一发布门：进程中断时已提交源仍可投递，游标没有越过尚未持久保存的投递数据。评测仍只使用通过原完整性检查的 completed raw run，T5 不接入，`radar_raw_v1` 不变。
4. 主消费者固定本轮队列上界、顺序消费，items、对应 runtime 与 batch ack 同一主库事务。主库 commit 后才删除 outbox；删除失败或中断后依据 ack 幂等重试，不再次覆盖新闻。未消费 outbox 自包含，raw 的既有 30 天滚动清理不删除它。
5. collector 保留 egress 和微信浏览器 preflight。A4 从真实 collector 完成日志取数，不把 ingest 成功当成 fetch 成功；A7 只使用与本批 items 一起导入的 runtime receipt。W1 仍由全处理阶段成功的 pipeline 恢复，解耦模式另须证明本轮消费了完整成功的 collector 轮；空队列和中断轮不充当恢复证据。

## Consequences

新增采集缓存库及待消费压缩 payload，积压期间多占磁盘；不增加抓取频率、源并发或 LLM 调用。队列消费恢复后释放已确认 payload。首次切换与回退都须在主写者互斥下同步游标并处理未投递数据，不允许直接清空队列或删库。旧 raw、T5 和用户 WIP 保留。

既有 ADR-047 原源解析、ADR-052/053 主库互斥、20260829-a7f1 同事务 X receipt、20260904-51d2 真实 fetch 完成时间及 20260904-d708 预检/恢复语义继续有效；本次只改变其接入位置，不放宽门槛。生产 cron/env 修改、应用 push、评分与判官变更不在本次本地放行内。

行动前未验证：事务故障/中断恢复、主库占锁期间采集、重复投递、配置身份变化、旧路径兼容、真实启用后的新数据。实现必须取得这些对应读数；上线许可不能由本 ADR 代替。

## 本地验证与审查结果

2026-09-16 定向回归 115 passed、2 skipped（8 个测试文件，26.26 秒）；覆盖临时 SQLite、主库锁持有/释放、2 个 loopback HTTP RSS 源、进程在单源提交后退出、主库提交后队列删除失败、3 种身份/载荷拒绝，以及采集/处理 shell、预检、W1 和 A4 消费路径。两项跳过为真实微信公众号联网测试，不是生产验证。ruff 通过；mypy 对 4 个改动 Python 模块检查无错误。

独立实现审查发现 A4 真告警入口传入预加载主日志时漏读 collector（HIGH、改动依附）；修复后同 reviewer 两问复核确认关闭。新增回归直接调用 collect_alert_signals/evaluate_rules，以 10 源全部 402、单轮健康、双轮健康三种输入验证报警与恢复判据。复核另发现 raw 路径类型改名遗漏异常分支（MEDIUM、类型修复依附），作者已统一引用并用环境变量/显式参数两种配置的同一 OSError 对照验证。无遗留 HIGH/CRITICAL、独立 findings 或承重未核实项；A7 仅静态核对事务接入，未取得新增生产端到端读数。

首次 reviewer 的告警复现意外触发远程定价刷新，HTTP 404 后回落，违反其禁外部网络约定；该次未进入成功缓存写入。随后使用显式本地 PricingCatalog 重新复现同样结果，最终回归禁止该刷新入口；未调用真实 LLM 或生产数据库。生产切换、实际增长体积/耗时及连续七天数据仍未验证，不由本地通过结果外推。
