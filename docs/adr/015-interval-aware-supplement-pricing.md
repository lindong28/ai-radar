# ADR-015：Supplement 定价按调用时间选择有效区间

- 状态：Accepted
- 日期：2026-08-11
- 范围：P1 查询时成本派生中的项目内 supplement；不覆盖 LiteLLM 上游价格历史或 ARK 价格权威性

## 决策

每条 supplement tariff 必须声明 `effective_from` 与可选的 `effective_to`。历史成本按 usage 的 `created_at` 选择区间；当前活跃单价按本次观测时刻选择。相同 `(provider, model)` 的区间必须有序、不重叠且 `effective_from < effective_to`；调价时关闭旧区间并追加新区间，不得就地改写历史区间。

当前 ARK supplement 的首个区间从现有来源发布日期 `2026-05-27` 起。更早的调用没有可支持的有效价，保持 `unpriced`。

## 取舍

只增加三组静态 supplement 的区间语义和构造期校验，不建设数据库价格历史、管理界面或外部计费同步。仅增加 `priced_as_of` 仍会用新价回算旧窗口，可能污染后续量结构比较；完整价格历史系统则超出 P1。

## 边界

本决策只保证 repo 内 supplement 不因未来修改而静默重算历史。ARK tariff 的权威来源、实际套餐计费语义仍未核实；P2 的 tariff-only 变化通知与 A6 不变性继续由 plan 的 V37 验证。

## 背景（补记，2026-08-20）

本 ADR 原文只有决策、取舍与边界三段，没有交代当时的处境。补记如下——标注「据正文推断」的部分是从原文取舍段的线索反推的，不是当时另有记录。

**处境。**成本不是从账单读来的，而是在查询时由 usage 行乘以单价派生（这一点由 ADR-016 定为唯一成本真相）。单价的来源分两类：LiteLLM 上游价格表覆盖的模型，以及上游没有覆盖、由本仓自己补一份静态报价的模型——后者即 supplement，当前是三组。问题出在 supplement 原本只有一个单价、没有时间维度：一旦调价就地改写那个数，全部历史窗口的成本会**跟着一起变**。而 A6（近 24 小时成本突变告警）和周报做的正是跨窗比较，历史被静默重算意味着一次调价可以伪装成一次调用量或模型组合的突变，或者反过来掩盖一次真实突变。

ARK 的首个区间起点取 `2026-05-27`，是因为那是现有报价来源的发布日期；更早的调用没有可支持的有效价，故保持 `unpriced` 而不是拿新价往回补。这条选择在代码里是硬的：`src/airadar/pricing.py` 的 supplement 构造期校验对缺 `effective_from` 的条目直接抛错，没有默认值可退。

**被否的方案。**

- **只加 `priced_as_of` 标记**（据正文推断：即记录「这个数是何时的价」，但仍只保留一份当前价）。问题是它不改变回算行为——历史窗口照样用新价重算，只是多了一个可以事后察觉的标记。而 A6 的比较发生在告警评估时，事后可察觉救不了当场的误报。
- **建数据库价格历史 / 价格管理界面 / 外部计费同步。**能力上是正解，但当时的目标（P1）只要求「repo 内 supplement 不因未来修改而静默重算历史」。三组静态报价加区间语义与构造期校验就能满足；一套价格历史系统的实现与运维成本与该目标不成比例。
- **不动。**即接受调价会重算历史。否决理由就是上面那条：它让成本告警与周报的跨窗比较失去可信度，而那正是这批 ADR 要建立的东西。

**明确没有解决的。**ARK tariff 的权威来源与实际套餐计费语义在本决策作出时仍未核实——本 ADR 保证的是「仓内这份报价不会静默重算历史」，不是「这份报价是对的」。
