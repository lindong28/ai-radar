# ADR-20260910-3f8b：论文类在排序键上降权 0.95，且只在排序键上

- Status: proposed（decision-review 复核中；放行后改 accepted）
- Date: 2026-09-10

## Context

精选页的论文占比长期高于参照产品 AIHOT。此前所有构成读数都不可信，本轮先修的是量具，三条：

1. **跨标注器**。TV 一直是拿我方分类器的标签比 AIHOT 的标签算的，而两者在同一批 1182 条内容上逐条一致率 55.3%（当前 prompt 下 68.5%），**光是标注分歧就值 0.312（当前 prompt 0.129）的总变差**——比要测的差距还大。修法是从远端 `captures/daily` 取回 AIHOT 自己发布的类别（3034 条 / 126 个正例，92.2% 按 URL 匹配到我方库），**两边都用它的标签**。slug→类别映射在题集上五类各 100% 一致，不是猜的。
2. **单日 TV 饱和于抽样噪声**。AIHOT 自己每天与它自己的合并均值差 0.269，按当日 5–35 条重抽的纯噪声 0.253，我方 0.262——三者无法区分。此前四个候选在这把尺子上全部读作噪声，据此判过四次「不泛化」，其中至少一次换合并口径后方向就变了。
3. **版面深度是混淆变量**。我方每天 40 条、AIHOT 十几条，而类别在排序上分布不均。同池同分只改深度：model 占比 29.2%（AIHOT 当日条数）/ 19.8%（40 条）/ 13.7%（整池），AIHOT 30.2%。**「model 缺口 −18pp 是排序缺陷」这条归因因此撤回**——同深度下基本无缺口。

量具修好后，同深度下真正剩下的超配是 industry +8.5pp 与 paper +5.7pp。整页人工标注（先在 60 条盲测上验过标注者：81.7% vs 生产分类器 69.9% vs 多数类基线 20.0%）给出 paper +14.7pp。逐条口径同向：我方打分器把 paper 放在候选池 71 分位，AIHOT 放 47 分位（n=2000）。维度上看得见——paper 的 density 6.30 与 authority 6.91 都是全场最高，而权重是 density 0.40 / significance 0.50 / authority 0.10。一篇又密又权威的预印本，对一份新闻摘要通常不是新闻。

## Decision

`select.CATEGORY_MULTIPLIERS = {"paper": 0.80}`，并新增 `select.ranking_key()`：**该系数只进 curate 的两处排序键**。

不进 `weighted_score`，因此不影响 `threshold >= 6.5`、`freshness_floor >= 4.0` 两道绝对闸，不影响 `dedup`（按 `weighted_score` 取幸存者），不影响归档的 `raw_weighted_score`，也不使 `SOURCE_QUOTA_SCORE_SEMANTICS` 变成假话。实测这个区分不是形式主义：

可复现入口：`scripts/eval/measure_curated_composition.py`（9 窗合并、两边都用 AIHOT 的标签）。2026-09-10 读数：

| 施加方式 | 命令 | paper 占比 | 合并 TV | 掉出候选池 |
|---|---|---|---|---|
| 不加 | `--multiplier paper=1.0` | 14.2% | 0.176 | — |
| **只进排序键（本决策，0.95）** | 默认 | **12.0%** | **0.156** | **0** |
| 只进排序键 @0.80 | `--multiplier paper=0.80` | 9.8% | 0.150 | 0 |
| 进闸 @0.80 | `--gate --multiplier paper=0.80` | 9.8% | 0.150 | **219** |

**第三行是关键**：把系数也喂给两道闸，页面结果**完全相同**，代价是 219 条整个失去入选资格。所以这不是"用效果换安全"，而是**同样的结果、严格更小的机制**。进闸那一版等于把 paper 的准入线抬到 8.125 分——那是一条类别专属的**收录规则**，与本系数拟合的秩效应不是同一机制。

（此前一版本 ADR 写"只进排序键保留 77% 的改善"，读数来自一个临时脚本，它两侧的日期口径不一致（AIHOT 用 UTC 日、我方用上海日）且把尾部槽位限窄到当日候选。那个数**不可复现**，已作废；上表来自修好后的仓内脚本。）

**作用面完整清单**（「只改顺序」这个说法会低估它，因为排序是相对的）：成员、名次、由名次线性派生的**显示分**、以及按显示分分档的**徽章**。后两项按类别不均匀，故 `about.html` 已明写。

**系数取 0.95 而非合并最优的 0.80**，因为决定它的不是合并读数而是单页行为：

| 系数 | 合并 paper / TV | 当前真实池 paper/40 |
|---|---|---|
| 1.00 | 14.2% / 0.176 | 4 |
| **0.95** | **12.0% / 0.156** | **3**（AIHOT 的 8.2% 对应 3.3） |
| 0.90 | 11.9% / 0.161 | 2 |
| 0.85 | 10.6% / 0.154 | 1 |
| 0.80 | 9.8% / **0.150** | **0** |

0.80 在合并口径上只赢 0.006，而该指标在 n=234 上没有标出带宽、这个差在噪声内；代价是在当时在跑的那个窗口上**页面一篇论文都没有**。用户 2026-09-10 在两组读数都摆出后裁决取 0.95。

**单页悬崖的机制**（不显然，故记下）：40 格中 36 格来自 `fresh`，即最新一天的约 200 条候选切在第 36 名。在这个池子里给一类降权会让它一步跨过切口——0.80 下 paper 的名次从 `[3, 18, 24, 25, 34]` 变成 `[31, 72, 86, 87, 97]`。

## 与既有决策的关系

- **部分 supersede [ADR-20260906-7c31](20260906-7c31-rank-on-weights-fitted-to-the-reference.md)**：该 ADR 把生产排序收敛为「同一个拟合权重向量完整定义」。本决策打破的正是这个更宽的性质——排序此后由权重向量**加**一张类别系数表定义。它**没有**重新引入 7c31 移除的东西：那是来源分层乘数、乘进 `weighted_score`，被取消的理由是排序方向反了且 tier 与内容类型混淆；本系数作用于内容类型本身、且不进 `weighted_score`。`curation_runs.weights_json` 因此改为记录整个排序函数（追加 `category_multipliers` 键；仓内无任何结构化读取方，纯追加）。
- **不与 [ISSUE-FIT-23](../issues/aihot-fit-eval.md) 冲突，两者量的不是同一个参数**。FIT-23（2026-09-06，n=2624）把**五类**偏移一起加进合成分，得 +0.0011（sd 0.0034，13/20），学到的 paper 偏移仅 +0.7。本轮独立重测同一形状得 −0.0135（12/20）——**同为零**。差别在参数个数：五个参数对着 121 条参照精选拟合会过拟合；**单参数版本 FIT-23 从未测过**，它在 20 seed 留出上是 +0.084（20/20，t=15.5）。按 enrich 戳分层不解释这个差（两种戳下均 20/20 为正）。
- **不与 [ADR-20260907-a1c4](20260907-a1c4-align-architecture-not-just-fields.md) 的接线撤回冲突**：那次把整个分数换成类别条件仿射映射 + 分位对齐**并移动了准入阈值**，TV 0.394→0.615。机制量级远大于一个排序期系数。它仍作为「类别项在此处失败过」的警告成立，这也是本决策只取一个类别、只在一处施加、并带发现通道的原因。

## Consequences

- 读者可见：论文排得更靠后，占比约 14.2%→12.0%；名次下移的论文显示分随之降低、徽章可能掉一档。`about.html` 与 CHANGELOG 已同步。
- **逆转成本不对称**：改回常量是一行，但 `/all` 与精选档案跨 run 累积，没有任何回滚路径能撤回已归档的错选（`admin curate rollback-quota` 只覆盖配额）。真实成本 = 40 条/轮 × 发现前的轮数。发现通道（T+1 轮的 smoke 检查、T+24h 与每周的合并对照、最晚发现时点一周）写在 `select.py` 的常量注释里，可复现入口是 `scripts/eval/measure_curated_composition.py`。**撤回判据只有一条：合并对照**。单轮上没有可用的判据——两个看着成立的都被证伪并记在注释里（「paper=0/40」错在仅排序也会产生它；「入选项 raw 分低于 6.5」错在 fresh 段的地板是 4.0 而非 6.5，实测真实 run 有 16 条）。更根本的是闸泄漏造成的是条目**缺席**，而缺席在输出里看不见，故不存在单轮判据。T+1 那步只验部署是否生效。
- **已知未闭合**（均记 `docs/issues/aihot-fit-eval.md`）：① aihot-fit 评测台不施加本系数，其次序类指标此后不跟踪生产排序；② 系数按当前 enrich 戳标定，而施加时不按戳过滤（fresh pool 里 27.7% 的 paper 标签来自旧戳，实测精确率 98% vs 94%、方向无害但属巧合），守卫是一个会在 enrich 戳变动时转红的测试，不是运行期过滤；③ 发现通道查不出「paper 数量正常但降错了条目、或补进来的更差」；④ **整页口径无可复现入口**：脚本只覆盖被 AIHOT 收录的约 30%（有偏子集），唯一的整页读数来自人工标注外推，标注者盲测一致率 81.7% 但 tutorial 召回仅 50%，故整页 paper 估计偏高；⑤ run 记录只固定了系数表，未固定每条候选的类别快照与 tie-breaker，而类别在本决策之后**首次**成为排序输入，故"精确复放次序"这条边界是本决策新增的。
