# ADR-061：公众号后台发现线整体废弃，发现层改由自建 Wechat2RSS 承担

- 状态：Accepted
- 日期：2026-08-20
- 范围：ADR-024 至 ADR-032 与 ADR-040 这条以公众号后台 `appmsg` / `appmsgpublish` family 为基础的发现线（含其 ledger 迁移语义 ADR-031、快照重复 URL 语义 ADR-032 与 searchbiz 身份验证语义 ADR-040），它的探路支线「微信读书只读 canary」ADR-033 至 ADR-038，以及后续加固 ADR-041、ADR-043 至 ADR-045 中依赖该 family 的部分；不改变微信正文抓取、展示边界与去重契约（后者见 ADR-059）

## 背景

ADR-024 开出的发现路线是：用操作者获授权的公众号后台登录态调用 `/cgi-bin/appmsgpublish`（并由 ADR-028、ADR-040 补上 `/cgi-bin/searchbiz` 的身份解析与验证），以 shadow canary 逐账号比对后再替换 Mp2RSS。ADR-025 至 ADR-030 是这条线上的探测节奏、比较语义、ledger 形状与 schema 演化；ADR-041、ADR-043 至 ADR-045 是它的不变量加固、一次性冷却豁免与平台错误码持久化。

2026-07-30 前后，这条线上的**第一页**请求开始稳定返回零结果并携带 `ret=200013`。这与历史上观察到的真频控不是同一现象：真频控表现为请求在若干轮后才被拒、退避与降 cadence 之后可恢复；本次是第一页即零结果，且等待与降低 cadence 均不恢复。上游两个独立实现同期报告同形状故障，可作旁证：`tmwgsicp/wechat-download-api#22` 与 `rachelos/we-mp-rss#440`。本仓 2026-08-17 的归因结论与之一致——该 family 对第三方账号已属平台级不可用，不是本项目的参数、身份映射或冷却策略问题。

证据细节见 `docs/references/wechat-discovery-evidence.md` 与 `docs/plans/20260816-mp2rss-replacement/`（两者本轮并行归档中）。

发现层的替代路径已经落地：ADR-059 决定以自建 Wechat2RSS 与 Mp2RSS 双跑取并集，并以「账号 + 归一化标题 + 5 分钟发布窗」跨源去重。也就是说，本 ADR 关闭的是一条已经有替代者的路线，不是把发现能力悬空。

## 备选方案

| 备选 | 否决理由 |
|---|---|
| **标 deprecated**（选中） | 决策本身没有被更好的决策推翻，是它依赖的平台能力被关闭。deprecated 恰好表达「不要再按它实施，但推理过程仍然可读」 |
| 标 superseded by ADR-059 | superseded 的语义是「同一问题有了更好的解法，按新的做」。ADR-059 解决的是双源并存下的身份与去重，并不接管 ADR-024–030 里的后台探测节奏、fakeid 解析、shadow 比较等具体契约——把它写成这些 ADR 的继任者，会让读者去 ADR-059 里找根本不存在的对应条款 |
| 不动旧标注，只在 ADR-059 里提一句 | ADR-024–030 是七条 accepted 状态的决策，外加三条加固。一个新读者从索引读下来，会把一条已经不存在的能力当作当前架构的一部分，并可能据此去调 cadence 或修 fakeid 解析——那是纯粹的浪费。索引状态列是这类读者唯一会看的地方 |
| 逐条改写旧 ADR 正文，删掉失效内容 | 违反 ADR 的 append-only 契约。这些文档的价值恰恰在于记录「当时依据什么这么决定」，事后改写会把一份决策记录变成一份现状描述 |

## 决策

**ADR-024 至 ADR-030 七条标记为 deprecated，理由统一指向本 ADR。**它们的正文一字不改，只在状态行追加一句标注。已有的局部 supersede 关系（ADR-024 被 ADR-025 / ADR-028 部分 supersede，ADR-028 的 searchbiz 验证语义被 ADR-040 supersede，等等）保留并列——deprecated 说的是整条线不再实施，不取消线内部各条之间原有的取代关系。

**ADR-031、ADR-032、ADR-040 同样标记为 deprecated。**它们不是这条线的"外围加固"，而是线内契约本身：ADR-031 规定该 family 的 ledger 历史迁移只保留可证明事实，ADR-032 规定后台单次响应含重复 URL 时显式失败，ADR-040 规定 `searchbiz` 只产 provisional mapping、再由返回文章 URL 的 public `biz` 完成身份验证。三者的实施对象都是已不可用的后台 family，与 ADR-024–030 同进退。ADR-040 对 ADR-028 的 supersede 标注保留并列。

**微信读书只读 canary（ADR-033 至 ADR-038）随本计划一并停止推进，标记为 deprecated。**这条线是同一个「替代 Mp2RSS」计划下的探路支线：它绕开后台 `fakeid`，改用一个专用 headed Chrome 的微信读书登录态做只读观察（ADR-034–038 逐版收紧证据 ledger 的可审计性）。停止的理由是计划本身出局，**不是**这条支线被平台封禁——最后一次真实观测（2026-08-14，schema v7）是 `/web/shelf/sync` 得到 HTTP 200 成功响应、但目标公众号不在书架，因而以 `blocked_no_shelf_entry` 停止，article-list 请求与动态头观察均未执行，替换结论停在 `not_validated`。把目标加入书架是一次需要单独授权的外部变更，本计划出局后不再申请。ADR-033–038 之间既有的逐版 supersede 关系保留并列。

**ADR-041、ADR-043 至 ADR-045 中依赖该 family 的部分随之失效**，但这四条不整篇标 deprecated：它们同时承载了 schema 演化纪律与「冷却必须由已记录的频控证据触发」这类仍然成立的通用约束。读者据本 ADR 判断其中与 `appmsgpublish` / `searchbiz` 直接相关的条款不再有实施对象。

**发现层的当前权威是 ADR-059。**

## 后果

- 索引状态列上，ADR-024–032、ADR-040 与 ADR-033–038 明确指向本 ADR，读者不会再把后台线或微信读书 canary 当作待实施或可回退的路径。
- 后台 family 相关的代码路径、配置键与 ledger schema 成为无实施对象的遗留物。本 ADR 不决定它们的清理时机与范围——那需要一次单独的评估（哪些 ledger 行是仍需保留的历史观测，哪些是可删的死代码），不在本决策面内。
- 若平台日后恢复该 family 的第三方可用性，重新启用不是撤销本 ADR 的标注，而是新开一条 ADR：届时的接口形状、身份映射与合规边界都需要重新取证，ADR-024–030 的读数已经不能直接复用。
- 本 ADR 不宣称后台线「原理上不可能」，只宣称在已取得的证据下它对本项目不可用。归因依据是零结果的形状（第一页即零 + `ret=200013` + 等待与降 cadence 无效）与两处上游独立复现，不是穷举了所有可能的参数组合。
