## M1 · 推荐理由：AIHOT 只给精选写，我们每条都写

### 形态

`reason` 存在 ⟺ `selected`，**两向零例外**：题集 78 条有理由 = 78 条 selected；r2 原始抓取 81 = 81。理由在 AIHOT 是**精选位的编辑按语**，不是逐条富化字段。

我们：`schema_v2.py:22` `why_recommend` 必填（35–90 字符），每条 enrich 都生成。

> **订正（decision-review blocker，我已自己核实）**：原文写「约 97% 的条目上我们向**读者展示**了一段参照物不展示的文本」——**这句是假的**。`src/airadar/web/routes/timeline.py:337` 是 `if row["rank"] is not None:`，`why_recommend` **只在有精选 rank 的条目上才附加**，公开界面本来就只在精选位显示理由。97% 只适用于**生成与存储**，不适用于展示。**M1 的头号理由（「读者可见的最大结构差别」）因此不成立**，剩下的是生成成本、存储、API 面与 reason 维天花板。
>
> **同时漏了一个更轻的备选**：保留逐条生成、只改展示——而主时间线**已经这样工作**。要动的其实只是「不再为非精选条目生成」，那是成本决策，不是展示对齐决策。

这也是 `reason` 维天花板测不出来的**结构性**原因：要拿到 AIHOT 对同一 URL 的两份理由，它必须两次都选中该条——实测 0/8（8 个重复摄入配对里 7 个恰好一侧被选中，0 个两侧都有）。**配对样本不是缺失，是按构造不存在。**

### 改法

| 方案 | 要引入什么 | 说明 |
|---|---|---|
| **A. 二段式（AIHOT 的架构）** | **多一次 LLM 调用** | enrich 只产 summary/tags/category；curate 选出精选后，对 top-k 单独跑一次"编辑按语"调用。字段变 `str \| None` |
| B. enrich 内条件生成 | 预处理：一个廉价的精选前置判据 | 精选发生在 curate（下游），enrich 时还不知道结果，只能用分数阈值近似——会与真正的精选集不一致 |
| C. 不改，当作我站特性 | 无 | 用户 2026-09-06 已定「一切以拟合 AIHOT 为最高优先级」，与此冲突 |

A 与 AIHOT 的架构同构，且**天然解决顺序问题**：curate 之后精选集已知。代价是 pipeline 多一段。

### 可测口径

- 结构事实（二值，直接可核）：非精选位不再产出理由。
- `reason_closeness` 的**配对集从"AIHOT 有理由的 77 条"变为"两边都精选的交集"**——注意这个 n 会更小，指标会更抖，这是采用 A 的已知代价而非收益。
- 成本：每轮 enrich 省下约 97% 的 reason 生成 token；改为对 top-k（当前约 2.8%）多一次调用。

### 不改的代价

`reason` 维天花板**永久不可测**（非暂时缺数据）；以及在 97% 的条目上继续付一次不进入展示的生成成本。（原文此处写「读者每张卡片都看得见」，同上已证伪。）

## M2 · 打分：AIHOT 的分数条件于类别，我们的六维没有类别项

### 形态

AIHOT 分数按主类单调差 **17.0** 分（本轮复现用户读数，逐位一致）：

| 类别 | n | AIHOT 均分 | 精选率 |
|---|---|---|---|
| model | 305 | 54.9 | 6.23% |
| industry | 512 | 49.5 | 1.95% |
| paper | 304 | 46.6 | 2.63% |
| product | 641 | 42.1 | 2.50% |
| tutorial | 979 | 37.9 | 2.55% |

`curator/weights.py` 的六维（relevance/density/recency/authority/engineering/significance）**没有任何类别项**，`weighted_score` 对所有类别用同一个线性组合。

### 关键架构事实（决定成本）

实测阶段顺序 **fetch → prefilter → score → enrich → curate → interpret**。`primary_category` 在 **enrich** 产出，在 score **之后**、但在 **curate 之前**。而 `weighted_score` 是在 curate 里被 `_load_candidates` 调用的。

所以：

- **在 curate 层加类别项** = 给 `_load_candidates` 的查询加一个 LEFT JOIN 取最近一条干净 enrich 行的 `primary_category`，外加 5 个参数。**不需要新的 LLM 调用，不需要重排 pipeline。**
- 让**打分模型本身**条件于类别 = category 必须早于 score，要重排 pipeline 或多一次调用。**成本高一个量级。**

### 读数（本轮实测）

共享斜率 + 类别哑变量（`y = a·base + b_c`），对半拆分、留出验证、5 个随机种子：

```
held-out Spearman   无类别项            0.6326
                    + AIHOT 真类别      0.6617   delta +0.0290   <- oracle feature，不可部署
                    + 我方预测类别重拟合  0.6549   delta +0.0223   <- 这才是可部署的数
                    + 真类别系数套我方类别 0.6430   delta +0.0104   <- 直接搬系数只剩三分之一
```

> **订正（decision-review blocker，我已独立复算确认）**：先前发布的 **+0.0294 是用 AIHOT 的真类别算的**，而生产只拿得到我方预测的类别（分类 agreement 仅 0.71）。四条读数在 2624 条同时有真类别与我方类别的行上算出，与评审者的独立复算逐位相符（他给 0.632579 / +0.029079 / +0.022287 / +0.010521）。**可部署的收益是 +0.0223，不是 +0.029**；且**不能把 AIHOT 拟合出的截距直接搬过来**——那样只剩 +0.0104。

**delta 真实但不大。** 对比历史步进：旧权重 0.4502 → 五维拟合 0.5925 → 加 `significance` 0.6331。这一步比其中任何一步都小。

拟合出的截距序**不等于**原始均值序：

```
model +27.4 · industry +25.8 · product +21.0 · tutorial +19.0 · paper +16.7   (slope a=4.65)
```

`paper` 从原始均值的第三位掉到截距的最后一位。

> **第二个 blocker（量纲）**：拟合出的 `b_c` 落在 AIHOT 的 0–100 回归量纲上，**不能原样加到我方 0–10 的 base score**。只比排序时等价变换至少要过 `b_c/a`，而阈值口径（`weighted_score >= 6.5` 进精选、`scoreTierClass` 的 80/65 档、tooltip 的「满分 10」）仍需另行定义。**M2 按现在的写法不可部署。**

> **第三个 blocker（逆转成本）**：错的截距会改变阈值准入，而 ADR-006 让曾被精选的条目**跨 run 累积归档**——恢复旧权重**不会自动撤回**已错误入选的历史；现有 `rollback-quota` 只认 quota 独有行，不是 score-change 的回滚器。**说明我方六维已经把那 17 分差距吃掉了大半，对 paper 甚至过度预测**；类别项买到的是残差，不是原始均值差。据 17 分差距推断的收益会高估。

> 方法学：第一版估计用「按类别取残差均值」直接加到基分上，得出 held-out ρ **下降**到 0.5178。那是估计量设错——我方基分在 0–9.65 量纲、AIHOT 在 0–93，+34~+49 的截距压过基分把类别内排序冲掉了。改成共享斜率的 OLS 才得到上面的读数。

### 不改的代价

拟合度停在基线一线；且 tutorial 占 979/2741（36%）而分数最低，我方会系统性高估该类。代价是**已量化的 +0.0223 held-out ρ**（我方预测类别上的可部署值，非 oracle 的 +0.029），不是"未知的提升空间"。

## M3 · 精选：不是按分数取 top-k，且与类别耦合

### 形态与证伪检验

用户给的证据是「均值序 ≠ 精选序（industry 分数第二高、精选率最低）」。**但均值不决定尾部**——若精选是全局取 top-k，精选率就由各类别分数分布的**形状**决定，均值序不一致并不构成反例。所以本轮直接检验了那个替代解释：

以 AIHOT 自己的分数取全局 top-78，与实际精选逐类别比较：

| 类别 | n | 实际精选 | 全局 top-K 预测 | 差 |
|---|---|---|---|---|
| tutorial | 979 | 25 | 15 | **+10** |
| model | 305 | 19 | 31 | **−12** |
| product | 641 | 16 | 1 | **+15** |
| industry | 512 | 10 | 27 | **−17** |
| paper | 304 | 8 | 4 | +4 |

**χ² = 251.0（df=4）。更直接的一条：AIHOT 精选的 78 条里有 49 条（63%）分数低于全局 top-78 的阈值 77.0。** 全局 top-k 假说被否定，且不是"大体成立但有偏"——它连一半都不到。

**按天分组后仍然否定**：精选条目只有 **28/76（37%）** 落在自己那一天的分数 top-k 里；每天精选数 1–18（mean 7.6，sd 5.5），也不是固定日配额。

> 口径边界：题集只含**与我方 URL 匹配上**的 AIHOT 条目，所以按天计数是下界、且受匹配偏差影响。上面三个结论都不依赖绝对计数（依赖的是同一集合内的相对分布），但精选数的绝对值不可外推到 AIHOT 全站。

### 这条与另外两条读数合起来意味着什么

1. 精选在**任何**分组下都不是分数的单调函数（本节）。
2. `selected` 只有 1/8 自洽，条件自洽率 **0/7**（95% 上界 ≈0.41），且两次记录发布时间不同、落进不同排名同期群——**它是 (条目, 同期群) 的属性，不是条目的属性**（ISSUE-FIT-30/33）。
3. 按 `selected` 拟合权重换 seed 就崩（ADR-499e）。

三条指向同一方向，但**结论要按 decision-review 收窄**：

> **原文写的是「`selected` 很可能不是这批数据上可学习的条目函数」「不投入拟合精选」——超出证据**。实测只覆盖：全局 top-k、按日 top-k、匹配成功的语料、以及 8 个高度选择偏差的重复对。而 **`selected_auc ≈ 0.79` 反而说明条目信号存在**，从它推不出「不值得拟合」。
>
> **收窄后的结论**：**当前不加固定的类别配额**——因为现有数据推不出配比数值（上表的偏离方向不稳定，且按天精选数 1–18）。这不等于「精选不可学」；有了新的 cohort 数据即可重启，且不污染历史。

这是本文件里唯一一条"建议不做"的改动。

### 若仍要动，改法

我们当前按来源配额（ADR-20260903-bc36）。可加的是**类别配比约束**（后处理，无新调用）——但上表说明我方要模仿的目标本身抖动很大，且 `product` 那格（实选 16 / 预测 1）提示 AIHOT 的精选带有分数之外的强成分。**在拿到"精选到底条件于什么"的答案之前，配比数字无从取值。**

### 不改的代价

`selected_auc` 停在 0.7907。但按第 2 点，那个天花板本身可能就在附近——ISSUE-FIT-30 已记「0.7907 可能已接近它能到的位置」。

## M4 · 分类：AIHOT 有兜底类因而有判定顺序，我们把五类平铺

### 形态

AIHOT 的 `tip` 是兜底类（"其余一切"）。有兜底类就有判定顺序：先判是否命中某个具体类，不命中才落兜底。我们把五个枚举平铺给模型一次选。

### 本轮实测的混淆矩阵（n=2624，行 = AIHOT，列 = 我方）

```
AIHOT\ours   model  product industry  paper tutorial  recall
model          234       18       12      2       25   80.4%
product         57      422       62      3       77   68.0%
industry        12       16      422      1       41   85.8%
paper           21        0       12    242       25   80.7%
tutorial       107       52      205     13      543   59.0%
ours-tot       431      508      713    261      711
overall agreement 71.0%
```

**关键不是 tutorial 召回 59.0%，而是它漏到哪里去了**：`tutorial→industry` **205 条**，是次大格（`tutorial→model` 107）的近两倍。同时我方 `industry` 列超额（预测 713 / 真值 512，精确率 59.2%）。

根因在 prompt 里看得见：我们对 `industry` 的定义写得极宽——"**也包括**具名公司或机构的官方表态与回应、安全事故与漏洞披露、服务中断、关于某公司下一步动作的爆料传闻，以及公司主办的活动、赛事……"。**这段话本身就把 industry 写成了一个兜底类。** 于是我方有两个兜底类在竞争，模型挑了定义更宽的那个。

### 改法（候选两段形态，交 T2 实测）

- **Stage 1**：只问"这条内容是否有一个**具体**的锚点落在 model / product / industry / paper 之一"，四类各用收紧的定义，**移除 industry 定义里的 catch-all 措辞**。
- **Stage 2**：Stage 1 未命中 → `tutorial`。

要引入什么：**一次额外调用**（两段各一次），或**同一次调用内的两步输出**（先输出四类判定 + 置信，再输出最终类）。T2 测的就是"是不是真需要拆成两次"。

### 可测口径

- 主口径：`category_agreement`（现 0.71，CI ±0.018）。
- 定向口径（更灵敏）：`tutorial` 召回（现 59.0%）与 `industry` 精确率（现 59.2%）——错配集中在这一对，整体 agreement 会稀释它。
- **对照必须两 arm 同 n、同题集、同判官**；`T2` 已按 n=300 定。

### n=300 对照的实测结果（2026-09-07，agent `t2-cat-ab`，四个 arm）

同题集、同 item（四份 `run.json` 的 `item_ids` 逐条相同）、同 seed 20260907、同模型 `deepseek-v4-pro-ga-260813`。变体做法是在生产 `SYSTEM_PROMPT` 里**定位替换分类段**，其余指令逐字节相同——所以分类指令是 arm 间唯一差异，`prompts_v2.py` 与 HEAD 逐字节一致。

| arm | 形态 | 调用/条 | agreement | CI | tutorial 召回 | industry 精确率 |
|---|---|---|---|---|---|---|
| **A** | 生产 prompt | 1 | **0.7200** | .667–.773 | 0.6168 (66/107) | 0.6164 (45/73) |
| B1 | 同一次调用两步输出 | 1 | 0.6711 | .621–.722 | 0.7642 (81/106) | 0.7500 (27/36) |
| B2 | 拆两次，分类 prompt 剥短 | 2 | 0.6923 | .639–.746 | 0.7642 (81/106) | 0.8519 (23/27) |
| B3 | 拆两次，分类 prompt = B1 逐字节 | 2 | 0.6600 | .603–.713 | 0.7850 (84/107) | 0.8214 (23/28) |

**B3 是必需的**：B1→B2 同时变了「一次变两次」与「完整文本变剥短文本」，读数不可归因。B3 把文本钉死，才使「拆不拆」成为单变量。

配对差值（同 item 逐条配对 bootstrap，1000 轮）：

| 对照 | agreement | tutorial 召回 | industry 精确率 |
|---|---|---|---|
| A→B1 | **−0.0503** (−.097,−.007) 更差 | +0.1509 更好 | +0.1336 更好 |
| A→B2 | −0.0268 (−.077,+.027) 测不出 | +0.1509 更好 | +0.2354 更好 |
| A→B3 | **−0.0600** (−.113,−.007) 更差 | +0.1682 更好 | +0.2050 更好 |
| **B1→B3**（一次 vs 两次，文本钉死） | −0.0134 (−.044,+.017) **测不出** | +0.0189 **测不出** | +0.0714 **测不出** |
| B2→B3（只差分类 prompt 文本） | **−0.0334** (−.064,−.003) 剥短的更好 | 测不出 | 测不出 |

### 三条结论

**① 本次 n=298 未检出「拆成两次」的收益。**（原文写的是「不需要拆」——**decision-review 指出那是把「未拒绝零差异」当成了等价性证明**：区间仍容许 agreement `+1.68pp`、tutorial 召回 `+5.65pp`、industry 精确率 `+18.52pp`。）B1 vs B3 三个读数全部测不出差别，却要付一倍调用。这是**有内容的零结果**而非缺读数：仪器在同 n 下分得开 +4.6pp 的召回移动，且在 A→B1/B2/B3 三个对照上都开了火；被否定的是 >1.7pp 的 agreement 提升（CI −.044,+.017），更小的没有。**要落地就取单次调用形态。**

**② 这套收紧按现在写法不该落地。** 它做到了承诺的事，代价是**兜底类换了一个而不是消失**：预测 tutorial 84→126~146（真值 106），**industry 召回 0.849→0.434~0.509**，B1/B3 上 **paper 召回 0.824→0.529**。没有一个 arm 好过 A。

**③ 更像真的那条杠杆不是「拆两次」，是「把写作指令从分类器上下文里拿掉」**（B2 vs B3，+0.033 分得开），并且是它救回了 paper 召回。干净测它要一个「**单次调用 + 剥短分类上下文**」的 arm，**没跑**——这是线索，不是结论。

> **测它之前必须先钉死「剥短」指什么**（T2 评审者交回的 caveat）：B2 的 stage-1 prompt 把**写作指令、标签词表、类别枚举**一并去掉了；而单次调用的 arm 仍然要在同一次 completion 里吐 tags，**词表与枚举去不掉**。所以「剥短」在那个 arm 上不可能是同一个意思，**B2↔B3 的 +0.033 不是它的预测值**。不先定清楚剥哪些，新 arm 会原样继承 B3 当初被加进来要消除的那个混淆。
>
> 复用现成的：`deepseek_v4_pro_twostage_split_full` 已在；新 arm 约等于「B2 的 stage-1 文本 + 一次调用吐完整 enrich JSON」，形状同 B1 的 provider。`scripts/t2/compare_arms.py` 接任意两个 run 目录，且已拒绝题集不匹配。（均在 worktree `t2-cat-twostage-20260907`，HEAD `b1df230`，未 push。）

### 两条读数纪律（本次实测确证）

- **只看定向口径会发出完全相反的建议**：tutorial 召回与 industry 精确率在**每个** B arm 上都显著改善。拦住它的是整体 agreement **加逐类矩阵**。
- **industry 精确率必须与 industry 召回一起读**：它的分母随 arm 从 73 塌到 27~36，精确率会机械性上涨。单看它支撑不了「分类变好」。

### 不改的代价

##### 第 3 条：一次失败的标定，与它为什么失败

统计量取「最近若干日捕获合并 → AIHOT `score_0_100` 的**九个十分位** p10, p20, …, p90 → 与快照 `aihot_knots` 同分位的**平均绝对差**」。这个选择本身站得住（见下表）。**定不下来的是阈值。**

先前这里写着「连续两次周评估 > 3.6 即刷新」，阈值取自「从当前题集总体重抽样」得到的 null 的 p95。**那个 null 是错的，且错法正是本仓 `docs/experiences/measurement.md` 记的那一类：读数在「标定过」与「什么也没标定」两种情况下形态相同。** null 从 `aihot-fit-new2d`（364 条）重抽样，而**要检验的那两个窗口，它们的并集就是这 364 条**——真实窗口按构造必然落在 null 带中央，于是「它们落在噪声范围内」这句话是个恒等式，不是读数。

换成真正的**无漂移 null**（从快照自己的 2624 行重抽样）之后，数字全变：

| null 的来源 | 九分位 mean，n=1200 的 p95（5 seed） |
|---|---|
| `aihot-fit-new2d`（先前用的，两个待检窗口就在里面） | 3.44 – 3.54 |
| **快照自己的 2624 行（无漂移 null）** | **1.12 – 1.22** |

而两个真实窗口的读数是 **3.22 / 2.16**，整个 new2d 池对快照的偏移是 **2.52**。两种 null 给出方向相反的结论：按前者，阈值 3.6 **在现有数据上永不开火**；按后者，**今天就该开火**。

**这个 2.52 是什么，两个窗口分辨不出来**：它可能是 AIHOT 真的漂了（v1 题集覆盖的时段 → 09-05/06），也可能只是两个日窗与一份跨多周题集之间的人群差异。**要分开它们，需要的是同一时段的多个窗口，而不是更聪明的统计量。**

##### 统计量的选择（这部分成立，与阈值无关）

| 统计量 | 两个真实窗口 | 无漂移 null n=1200 p95 |
|---|---|---|
| 全域 p0…p100 的 `max` | 9.0 / 10.0 | 7.00 |
| 全域 p0…p100 的 `mean` | 3.73 / 3.40 | 1.45 – 1.55 |
| 九分位的 `max` | 6.0 / 4.0 | 2.00 |
| **九分位的 `mean`** | **3.22 / 2.16** | **1.12 – 1.22** |

取九分位 mean 的理由是**分辨率**而非分离度：全域 max 的取值集合几乎离散（真实窗口 9.0 / 10.0 全是整数），`mean` 平滑得多；而全域比九分位多的那两端是次序统计量、方差最大。**「全域」指哪些分位是规格的一部分**——上表取 p0, p10, …, p100 共 11 点；取全部 101 个整数分位会得到另一组数（复核者按后者读，得 3.44 / 2.50）。同理「九分位」是 p10, p20, …, p90 共 9 点，不是 p10…p90 的 81 个整数分位。

##### 要把第 3 条定下来还缺什么
