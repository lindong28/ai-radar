## 对象、题集与计算链

所有叶子当前只提供执行说明与 `metrics.json` 设计定义，尚无新 runner/scorer 接线，不可当成可运行评测命令。以下源码是对象定位，不表示新体系已验证其输出。

| 对象与稳定 target | benchmark／执行说明 | 输入 → 参考／预测与计算链 |
|---|---|---|
| O1 全部 AI 动态收录 · `news-admission` | [aihot-all-members](../../evals/news-admission/aihot-all-members/README.md) | 完整候选池 U → AIHOT 全部动态 R／我方实际准入 C；[prefilter](../../src/airadar/prefilter/runner.py) 加实际影响收录的确定性条件 → 集合 precision/recall |
| O2 可见评分 · `visible-score` | [aihot-visible-score](../../evals/visible-score/aihot-visible-score/README.md) | 配对 raw → AIHOT 可见分／预测可见分；[scorer](../../src/airadar/scorer/runner.py) 加必要分值转换 → MAE |
| O3 内容富化 · `content-enrichment` | [aihot-enrichment](../../evals/content-enrichment/aihot-enrichment/README.md) | 配对 raw → 分类、标签、标题、摘要、推荐理由；[enrich-v2](../../src/airadar/enrich/runner_v2.py) 加必要显示转换 → 按字段计分 |
| O4 精选成员 · `featured-members` | [aihot-featured-members](../../evals/featured-members/aihot-featured-members/README.md) | 固定完整池、预测分及规则所需其他输入 → AIHOT 精选 R／我方精选 C；[curator](../../src/airadar/curator/select.py) → 集合 precision/recall |

O1 不能把 prefilter 的 true 当成页面已收录，[timeline](../../src/airadar/web/routes/timeline.py) 中影响准入的 relevance 条件也属于边界。O2 计算最终展示量纲的分数；当前 `rank_linear_v1` 排名映射及前端乘 10 取整意味着中间分不能直接代替展示分，具体拟合与转换方案待实施。

O3 五字段独立入题，共享同一次 enrich 输出；不要求生产拆成五次调用。类别对应关系先固定；明确空标签可作为参考，未知或未捕获不能补空。标签不比较顺序，也不先删除候选多余标签。标题、摘要和推荐理由的判官读取 raw、候选字段和 AIHOT 参考，模型、prompt、输出类型、量表、最终指标及校验通过条件尚未设计。

O4 先固定预测分再调阈值等选择规则，调规则不重跑评分。规则需要类别或累积归档初态时一并固定；不要求重建 AIHOT 内部运行或全部生产历史。AIHOT 精选成员和数量只供计分，不能直接决定选择谁或选几条。

范围排除 T5、旧评测 runs、微信独有文章解读、interpret/KB 和微信专用来源；共同主新闻源里的微信原文不按域名一刀切排除。身份匹配与重复抓取合并仅服务准确计数，不增加身份、内容组织、排序或去重质量指标，也不恢复独立 O5／最终页面总对象。

### 指标定义入口

| 对象 | 机器可读定义 | 已定义计算 |
|---|---|---|
| O1 | [metrics.json](../../evals/news-admission/aihot-all-members/metrics.json) | precision=`|C∩R|/|C|`；recall=`|C∩R|/|R|` |
| O2 | [metrics.json](../../evals/visible-score/aihot-visible-score/metrics.json) | MAE=`Σ|预测可见分−参考可见分|/N`，量纲与参考一致 |
| O3 | [metrics.json](../../evals/content-enrichment/aihot-enrichment/metrics.json) | 类别 accuracy；标签 exact-set accuracy；三类文本尚无指标定义 |
| O4 | [metrics.json](../../evals/featured-members/aihot-featured-members/metrics.json) | precision=`|C∩R|/|C|`；recall=`|C∩R|/|R|` |

七个定义按对象计数：O1 两个、O2 一个、O3 两个、O4 两个；不是已有成绩。方向、单位和定义来源统一由各叶子的 JSON 维护，当前没有已接入它们的分析消费者。JSON 使用 `schema_version: 1`、`benchmark_slug`、`metrics`；每项含 `task`、`metric_name`、`unit`、`direction`、`definition`、`source`，完整语义见叶子 README。

分母为零记 N/A，不冒空集满分。失败保留题和状态；O2 有失败时完整题集 MAE 未完成，成功子集仅为诊断。O3 候选失败或字段缺失算不一致，即使参考标签为空也不能得分。O1/O4 失败不能伪装成成功空输出；不能明确计数时标结果不完整，不能从成功子集宣称全体改善。数据缺口、失败数和分母留作解释信息，不增设优化 KPI。

## 阶段交付与验收

以下是后续实施 session 的接续顺序，不是本轮已经执行的计划或运行记录。

| 阶段 | 交付 | 可观察验收与下一步归属 |
|---|---|---|
| 1. 来源／窗口核查与冻结 | S、连续合格窗口、两侧 raw/参考快照及来源证据、缺口清单 | 数据实施 agent 按 [持续采集说明](../operations/continuous-eval-data.md) 核逐源应采集槽、完整参照和正文依赖，再冻结；交出实际窗口、来源数、唯一新闻数与各对象可用量 |
| 2. 四对象建题与确定性计分 | 稳定题 id、raw/参考配对、开发与回归划分、七指标 scorer 及四叶子执行入口 | 实施 agent 用已冻结题集核输入与参考分离；对非空/零分母、漏收/多收、未知/明确空、缺输入/调用失败取区分读数；O2 核最终量纲，O4 核固定分数 |
| 3. 文本判官设计与用户校验 | 标题、摘要、理由的判官与量表；带来源的用户判断及独立核对样本 | 判官实施 agent 补方案，用户核对少量好/坏样本；未用于调判官的样本验证能否分开。未通过前文本分只作未采信诊断，不驱动优化；确定性指标可独立使用 |
| 4. 基线与离线迭代 | 同题同尺的 baseline/候选结果、逐题差异、归因及回归记录 | 运行 agent 先落实预算、并发和预定改善口径；保留失败轮。比较 O4 规则时固定池与预测分；改 scorer 后更新对应预测并复测 O4，标明输入版本变化 |

当前阻塞后续取数的是阶段 1 的实际合格范围未核定，而非已经测出某对象低分。文本判官待设计，不应阻塞阶段 2 的确定性计分建设。题量与达标阈值均未指定；不能导入旧实验阈值，也不能据七个定义文件宣称已经建立完整体系。

### 数据准入的实施检查

1. 从现有采集记录取 Radar 过滤前 FetchedItem 与 AIHOT 原始页面/API/SSR 证据；具体 coverage/freeze 命令与参数来源见采集运维说明。本档不另造新 runner CLI。
2. 在拟用窗口内，来源 S 必须同时满足 AIHOT 出现证据与入口语义相同；聚合入口和原站不可只按相同 URL 合并。按 S 的实际启用时段与调度核连续性，排除来源的失败不自动否定 S。
3. 缺轮、未完成、来源失败、损坏正文均不完整；成功空结果可用，304 须能追到归档正文。完整性是指定来源的系统抓取覆盖，不保证源站所有曾发布文章。
4. 原期望 `[2026-09-06T00:00:00+08:00, 2026-09-14T00:00:00+08:00)` 是 8 天、192 小时，不能写成已有可用量；有缺口只取实际连续合格子窗，不拼散日或用当前数据库回填。
5. U 保留 S 内全部过滤前新闻，不能先缩成两站 URL 交集。只有完整 R 才能把 U 中未出现项标 0，且 0 只表示 AIHOT 未收录。R 中缺 Radar raw 的项仍在 O1/O4 recall 分母，并列缺输入数。
6. 固定同篇新闻的 raw 正文版本，保留观察时间与参照归窗规则。版本冲突不挑效果最好的一版；AIHOT 输入版本未知时，不把全部差异归因于我方模型。
7. 各字段独立筛选参考：缺可见分数只影响 O2；缺推荐理由只影响 O3 理由题。开发/回归分开，同新闻/版本不能跨组反复调答案。

本轮没有运行数据盘点、冻结或远端共享存储检查。运维文档里的旧首轮抓取数量、旧十四日盘点和本地业务数据库行数均不是本设计的合格题量。

下列 `./` 相对 AI Radar 项目根。四个 target/benchmark slug 使用上表的实际名称；版本由题集冻结后确定，不用模型名替代稳定对象身份。

| 对象执行／评分代码 | `./evals/<target>/<benchmark>/`；本轮各叶子只有 README 与指标定义。实施时在此提供权威入口，共用 runner/scorer 保留单一实现 |
| 原始逐轮产物 | 规划为 `./runs/<target>/<benchmark>/<version>/<YYYY-MM-DD>/<HH-mm-ss>/`；本轮未建立新体系轮次 |
| 运行元数据与指标查询 | 规划为 `./experiments/<target>/<benchmark>/<version>/<YYYY-MM-DD>/<HH-mm-ss>/`；本轮未建立 `metadata.json`、叶子 `metrics/summary.json` 或总表 `experiments/metrics/summary.json` |
| 人工评价 | 规划为项目根 `./human-evals/`；本轮未建立，零新增票据，不建空票伪装能力 |

共享题库保存 raw、适配题和参考的关系；题 id 应解析到固定正文与对应可观察参考，模型只读输入，参考只给计分器/判官。保留 AIHOT 原始观察依据和字段缺失语义，Git 中的定义及离线副本须注明共享版本对应关系，不把私有原文提交主仓。版本物化与访问确认归数据实施 agent。

新轮目录时间采用 UTC 的 `YYYY-MM-DD/HH-mm-ss`，`runs/` 与 `experiments/` 同分区。创建时间与真实开始时间分别记录，同秒冲突报错，不覆盖或合并旧轮；历史导入的真实时间未知就留空，不能用迁移时刻补成运行时刻。

现有 [src/airadar/eval/aihot_fit](../../src/airadar/eval/aihot_fit/) 可逐组件审视复用；它的旧 runner、阈值和资产布局不自动成为新体系入口。本次没有迁移代码或历史资产，也未把新叶子链接到旧 CLI 当作接线完成。是否复用由实施 agent 核输入、评分语义和实际 caller 后记录在叶子 README。

### 一轮运行应留下什么

| 时点 | 运行 agent 的操作与可找回信息 |
|---|---|
| 开始登记 | 对象/benchmark/题集版本、run/attempt、输入与参考身份、对象配置和基线、计划分母与子集、scorer 及适用判官/校验身份；先写改善口径 |
| 运行中 | 保存逐题输出、预测状态、分数和判词原件；记录各阶段起止/计时边界、实际题数、失败/重试/取消。共享 enrich 输出只保存一次并引用 |
| 成功／失败／中断收尾 | 补实际完成量、缺失原因及资产位置；已算未采信和未计算分开，未知 usage/成本不填零；保留失败轮而非只记录存活调用 |
| 更新查询与当前快照 | 原 scorer 是数值来源；叶子摘要引用全部汇总及缺分状态，总表只汇合已登记叶子、不跨 benchmark 平均。核来源能解析后更新轮次与 tracked 当前结论 |

新查询记录至少能定位 `target_slug`、`benchmark_slug`/`benchmark_version`、`run_id`、`task`、指标名/原精度值/单位、状态与原因、原始来源和 metadata。具体 schema 与生成器尚未实现，实施 agent 沿既有产物补足，不复制多份事实或手填一份脱离 scorer 的成绩。指标定义 JSON 与每轮成绩分开维护；分析消费者接入时从定义读方向，从已归档结果读值，缺定义/缺分/未采信值不能冒成较优值。

并发、参数入口、限制的工作单位、共享资源容量与调用预算尚未设计，不能沿用旧 runner 配置当作本体系默认。实施 session 在运行前确认；每轮区分配置并发和观测并发，记录阶段耗时、时钟来源与不能分摊的共享开销。凭据沿项目环境安全取得，文档与资产不保存密钥。

本设计当前目标口径在三份 foundations 正文；没有阈值、指标序列或归因成绩。首次实跑后，运行 agent 在既有 [AIHOT 台账](../issues/aihot-fit-eval.md) 明确划出新体系身份、序列与假设状态，并记录最后同步轮次，不能混进旧实验趋势。

## 当前交接边界

已完成的是设计导航、四对象入口和七个机器可读指标定义。新体系题库未冻结，runner/scorer 未接通，文本判官与用户校验待建立；共享题库、结果查询与目录自动检查也未建立。本轮未取数据量、未跑模型或评测、未迁移旧资产、未改生产。
