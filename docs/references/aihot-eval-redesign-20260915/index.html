题库建法：先分清对象，再做配对

逐条题 · 输入是什么，输出该像谁

保留原始标题、正文/媒体证据、真实来源身份、发表/发现/抓取时间及版本。AIHOT 标题、评分、分类、标签、精选状态和理由只在 gold 侧，不交给候选模型。

先用原文 URL/平台 ID 找候选，再核来源、内容版本与时点；一对多先保留并诊断，不取第一条。不同来源的转载是相关事件，不自动等价输入。

题目结果：稳定题 ID → 输入快照 → 各字段的参考值和观察证据 → 分组/切分 → 适用与缺失原因。

整池题 · 在这一刻实际选中了什么

以共同来源在观察时刻前的完整可用池为输入，保留未入选候选与历史状态；运行实际准入、评分、富化、去重、精选与归档。

我方按自身规则产生自然数量的集合，不预知 AIHOT 入选数。精确 URL 集合是主指标，跨来源同事件匹配另报，不能把转载差异偷偷抹掉。

缺完整池或观察快照时：集合指标标未核实；已具备字段的逐条诊断仍可做，但不得外推为完整 14 日结论。

来源对齐是建题前置，不是字符串相等。 为双方来源建立显式对照：平台账号 / feed / 原站域名、source kind、可见与启用状态。共同源分母单独公布；参照独有、我方独有和未映射来源分别列出，不通过缩小交集隐藏覆盖缺口。

切分与时间状态

拟在完整 14 日建成后按时间分为 8 日开发、3 日验证、3 日封存；同一事件跨日聚类后整组归最早的切分，后段重复不再作为独立题，报告实际剩余天数/事件数/来源数。当前 14 日里部分样本已被历史迭代使用，不能称作“从未见过的测试集”：只能先做封存回归，未来另取未用新窗才能支持独立泛化。不会悄悄延长本次 14 日来掩盖这一点。

冻结当前原文后用最新代码重算，叫“当前代码的历史语料实验”；只有输入版本、时间水位和历史状态均能闭合时，才叫“同期历史重放”。每个候选在同一原始暖启动语料上建立自己的状态，禁止把基线的后验精选/enrich 灌进候选，或把未来信息用到过去。

L1 · METRICS

逐项回答“像在哪里、不像在哪里”，不合成一个总分。

每个质量数旁都带参考可观测率、配对成功率、实际到达率与有效样本数。缺失输出在覆盖轴计入失败，不从总体消失；缺参考值是未知，不伪造错误。按日、来源、类别和精选/非精选分层展示，但不把同一新闻或同一事件反复当独立样本。

用户可见维度主指标与单位分母 / 观察面反例与归因读数
最终显示分MAE（分）、平均偏差、绝对误差 P90；分差分布。Spearman 仅辅助同源配对且双方该面有显示分的条目；另报目标条目显示分覆盖率零误差构造输出不裁剪地 +10：MAE=10，排序不变；追溯 raw→rank→display
分类与分栏逐条一致率、macro-F1、每类 P/R、混淆矩阵；分栏归属正确率有参考类别的共同源题；歧义/无类别单列多数类基线；TV 只诊断构成，不能替代逐条正确
可见标签精确集合 micro/macro P/R/F1；语义等价另报；标签缺失率参考标签可判的新闻；未映射预测标签也进 precision 分母映射只从开发集冻结；原样文本保留，不能先删掉“不像参考”的标签
精选集合实际集合 precision / recall / F1；漏选清单、额外入选数；同事件命中作为次级读数固定共同来源与观察时刻、完整候选池；分别报整窗归档与页面可见集合缺抓取和被筛掉分别归因；未知参考成员不给假负例
精选顺序与版面深度首屏/前 40 实际成员 P/R；共同成员顺序差异；NDCG 仅在参考顺序/分值含义可核时启用双方各自自然页面深度；同时报告条数差，不以 oracle k 改我方产出分离“内容多一倍”与“排序错”；按发布时间排序的首页不当评分榜
标题事实/主体/事件覆盖，新增断言错误，语言与信息焦点接近度；可接受率最终可见标题；参考/原文都交判官，候选不看 gold同义改写应可接受；单主体置换应定位到错误
摘要核心事实覆盖、无依据断言率、冗余与长度差；可接受率最终摘要含 fallback；截断后可见内容与完整文本分别记录空白、通用空话、关键限制遗漏、数字反转
精选推荐理由具体价值是否与参考同向、是否有原文依据、是否通用模板；可接受率共同精选用于理由质量；目标精选未到达/无理由另列全目标覆盖不能“漏选一条”就让那条差理由从分母消失
来源 / 时间 / 链接 / 可见性映射一致、时间语义、跳转目标、同文跨面字段差异；页面到达率目标共同源新闻，按首页 / 全部动态 / 分类筛选分面发布/发现时间不混用；跳转外站的在线可达性不冒充离线已证

达标线：提案，不是已批准标准

初始讨论值：最终分 MAE ≤5、P90 ≤10；类别 macro-F1 ≥0.85；标签 F1 ≥0.80；精选 precision 与 recall 均 ≥0.80；标题、摘要、理由分别可接受率 ≥0.90。

这些数值尚无用户授权或本轮校准依据。 不进入可执行闸。先展示实际误差分布与边界案例，再由你确认“足够接近”；不能为了过线删题、换窗或调低标准。

重大失实单独列出。“本次样本未见”不代表总体发生率为 0，也不以别的维度高分抵消。

改善与达标分开

候选在同一题、同一判官和同一尺度上与最新代码基线配对。先报告差值、区间和受损案例，再判断是否采纳；“比以前好”不等于“已足够接近”。

自动指标尽可能全量。语义抽样使用预定分层权重；诊断困难题可过采样，但不能把困难题比例当总体比例。区间按事件聚类，必要时按日分块；仅 14 日时明确跨时间泛化的不确定性。

不自动删除达标困难的维度；证据不足的维度标未核实，已可信的读数继续保留。

L1 · JUDGE & VALIDATION

能直接计算的不用模型；必须判断语义的先校准尺子。

确定性判定器

评分差、类别对应、标签字面集合、精选成员和缺失状态直接计算。人工确认来源/类别映射后冻结；“调用了 LLM”不为这些数字增信。

校验使用手算小例子与故障注入：整体分数平移、漏题、全猜多数类、空标签、重复新闻和时间边界。指标应该在哪个维度变、哪个不变，都有预期。

带标签的语义判官

标题、摘要、推荐理由分开判。输入是原文证据 + AIHOT 参照 + 匿名候选；输出离散缺陷/可接受判定、对应片段和缺证原因，不要无锚的“接近度 8 分”。

拟用与候选不同模型家族的单判官；先小批对人工标签验证后再冻结具体 model / prompt / parser。AIHOT 内部供应商未知，不宣称满足双方跨供应商盲判。无需双判官常驻。

判官维度可接受必须指出的问题无法判断
标题主体、动作、核心进展同向，允许改写主体/数字反转、加入参考和原文都没有的结论、遗漏事件核心原文或参照缺失，事件配对不明
摘要保留参考的重要信息与关键限制，不抄措辞也可无依据细节、把试验变上线、遗漏否定/条件、模板空话输入本身过短，无法判事实覆盖
推荐理由说明这条新闻的具体价值，论据可定位只有“值得关注”、价值点错位、把营销主张当客观结论不是该观察中的精选，或无参考理由可比
标签语义规范同义词、品牌别名可对上同一概念泛化过度、额外无依据主题、丢掉关键主题参考明确缺失或别名未经确认

判官校验按真实难度建，不只用“原文对原文”和“完全错配”

准备初始校验题

拟取 60 个真实分层案例，覆盖各文本维度、类别、来源、精选/普通、不同长度及近边界质量；另取 24 个明确构造的对照。数量是起始预算提案，不是充分性证明。

取得可信标签

人工先独立判可接受/不可接受/缺证，再用于检验模型；agent 预标与用户票分开。当前用户票为 0，不能假称已校验或训练时用过的例子是校验集。

冻结可采信范围

按维度报告误报、漏报、重复一致性和位置交换差异及区间。只在人工分歧可解释、误差可接受的维度启用判官；具体容忍线交你确认。

随机与常量地板、失败时怎么落

分类均匀随机的 accuracy 为 1/K；按真实类别比例独立采样的期望为 Σp²；多数类常量为 max(p)。三个数不同，不写成一个通用 50%。宏 F1 用同题模拟/手算，不能从 accuracy 地板照搬。

在 N 个候选中有 P 个参考精选，独立均匀选 K 个时，期望 precision=P/N、recall=K/N（P、K>0）。P=0/K=0 单列约定，不除以零；始终选空的候选必须在覆盖和召回面暴露。连续分数用开发集常量中位数作 MAE 基线，独立置换作排名对照。

语义判官以人工逐题标签为校验对象：报类别平衡后的准确性及关键缺陷的 precision/recall，和多数类基线比较。因为此处有 per-case 标签，不用“盲猜分不出两个系统”代替标签正确性。

模型超时、输出非法、证据不足分别记无效或无法判断，不转成 0 分或通过。校验失败只暂停相应语义维度的采信与据此优化；自动指标、原始产物和其它有效维度不作废。

参考不是事实真理：对齐度和原文事实一致性分开。AIHOT 有明显错误时保留其原始输出并标注争议，不让候选靠复制错误获得“高质量”。来源正文只当数据，判官不执行其中的指令，不访问文中路径或链接。

L2 ASSETS / L3 GOVERNANCE

留下每轮能复盘的最小资产，而不是再建一个治理项目。

L1 回答效果，L2 保存过程和失败案例，L3 限定哪些结论能采信。三层相互引用，但 L3 合规不意味着 L1 达标；某条历史身份缺失，也不要求把所有已付费结果全部重跑。

L2 资产具体保存什么谁据此做什么
① 题集稳定 ID、原始输入快照、源/时间/事件组、独立参考字段与观察证据、切分与缺失builder 复建同题；人检查是否同源、gold 是否泄漏
② 逐题输出各生产阶段原始输出、错误、实际页面投影与未到达原因；run/对象/代码身份开发者定位差异发生在哪一段
③ 指标逐题差、分母、分层、区间、基线/候选配对；指标版本与输出引用报告回答改善/退步/未核实，不只存一个总均值
④ 用户票题目与产物版本、用户原始判断和自由文本、时间；没有就是 0 票校准“足够接近”，与 agent 预标分开
⑤ 判官与调用记录model/prompt/parser 身份、输入引用、逐题判词和证据、校验结果；发出前登记 attempt复核误判；超时/取消也在账上，未知费用不等于零
⑥ 归因假设问题、适用输入、差异预测、对照、观察、支持/反驳/未定、下一步区分“看起来像原因”和实际支持的原因
⑦ 轮次账本目标、基线、候选、资产引用、结果、采纳/拒绝/未定、花费与剩余动作跨 session 接续，不从旧对话猜进度

L3 · 最少五项采信检查

  1. 实际代码、模型/prompt、输入字节与记录身份一致。
  2. gold 不进候选；开发、验证、封存与已见样本分开。
  3. 候选与基线在同一输入与尺子上比较，旧身份不回填。
  4. 判官只在已校验维度驱动语义结论，未知单列。
  5. 优化采纳要有差异预测与对照证据；未证实的归因不直接升级为修复结论。

这些检查嵌入实际 builder/run/judge/report/adopt 调用路径；没有 caller 的脚本不称作已接入闸。

资产寿命与失效范围

代码、设计、题集清单与关键轮次结论进 Git；大体量原始输入和逐题结果放持久评测资产目录并由摘要引用，不只存临时目录。

只要仍作基线或被活跃回归引用，原始输入/输出/判官依据不随日常 14/30 天清理删除。具体目录与容量在实施前按实际体积定，不在报告里承诺未量过的 GB 数。

OFFLINE ITERATION

每一轮只回答一个可证伪的问题。

完整性与身份 → 最新代码基线 → 失败簇 → 差异预测 → 最小干预 → 同题全维回归 → 采纳 / 拒绝 / 证据不足

先刻画参考

读取配对案例，提炼输入→AIHOT 判断的候选规则：模型发布、教程、论文、产品更新分别看什么事实。定义可读就读定义；定义不可读就从开发样本验证，不用边际比例倒推。

把误差归到链路

分成输入缺失、准入误杀、评分刻度、类别混淆、标签、精选策略、文案、展示改写。每簇列代表题和影响人数/条目，按用户可见损失排序。

提出差异预测

例如“分数误差来自 rank 映射”：只换显示映射应改变 MAE，不改变入选集合；若集合也变了，则实现混入了别的变量。

先诊断，再优化

消融可以临时注入参考类别或固定中间值来隔离成因，但标为诊断，不计候选成绩、不进入部署。只有支持的原因才形成候选改动。

复用成果、配对重算

冻结题与尺子；命中缓存则复用原始调用结果。重算依赖链下游并覆盖所有目标维度，避免只验证正在优化的那一列。

给出有限结论

列改善、退步、未核实和归因证据；达标但其它维度退步不能自动采纳。部署另行安排，不从离线通过直接写生产库。
