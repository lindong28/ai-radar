四个对象，只测要拟合的内容

全部 AI 动态看收录，评分看可见分，富化按字段分别建题，精选只看成员。能确定性比较的地方，不引入 LLM 判官。

删除“事实身份”“内容组织”优化目标；不测列表与精选的顺序、去重质量；不再单设“最终可见内容”评测对象。

这是职责关系，不规定实际调用顺序。O4 复用上游结果，不新增一次 LLM 调用；规则未消费的上游字段不构成额外依赖。

“遗漏”就是 recall 中未召回的参考新闻；“额外条目”就是 precision 中不被参考收录的输出。它们不是额外目标。用唯一新闻身份做集合计数，也不是另建“事实身份”或“去重质量”评测。

为什么还需说明两处现有输出转换？

本轮只读检查的代码基线为 262e59a，不是生产实况审计。“全部 AI 动态”当前除 prefilter 外还受 relevance 门槛影响；精选当前有按排名重新映射展示分的逻辑。因此 O1 包含实际影响收录的规则，O2 包含产生可见分所需的确定性变换。

这样可避免“prefilter 通过了但列表看不到”或“原始分拟合了但展示分又被覆盖”。不新增评测对象，也不要求保留这些旧规则；后续如何调整实现尚未决定。

02

一份原始数据，按对象派生题集

输入：Radar 过滤前新闻

同一连续窗口、共同来源的全量候选。保留当时采集的原始版本，包括之后被过滤的新闻；不只留已在 AIHOT 找到匹配的条目。

参考：AIHOT 页面内容

同窗全部 AI 动态和精选的成员，以及实际可见的分数、类别、标签、标题、摘要和推荐理由。参考字段未知不填默认值。

期望窗口仍是 9/06—9/13。UTC+8，含首尾 8 天 / 192 小时；这是期望范围，不是已核定可用量。本轮没有重新盘点或冻结数据。

  • 来源须有共同来源证据。窗口须完整连续；宁缩到完整段，不拼接断续片段，不把采集失败当成功空结果。
  • T5 旧实验不作为原始数据；微信独有解读页面及其专用数据不入本次题集。共享新闻中的微信原文不按域名一刀切；网站所需数据不删除。
  • 评分题仅保留有 AIHOT 可见分数且有 Radar raw 的新闻；富化题按字段单独选样。缺分只影响评分题，不从其他题集删除该新闻。
  • O1 / O4 的参照必须是完整成员集合。AIHOT 有而 Radar 缺 raw 的成员仍留在总体 recall 分母，旁列缺输入数；它们不是靠调 prompt 能补出的输入。
  • 在完整参照里未出现的候选，可以标“AIHOT 未收录”；不能把这一标签解释为客观“非 AI”或“低质量”。
完整同窗 raw + 页面参照→按对象 / 字段建题→固定输入与参考→同题比较版本

每个对象的最小三层设计

L1 写清怎么算；L2 只留复盘需要的结果；L3 只写适用的基本约束。没有把模板槽位变成新增指标或强制复杂系统。

03

共用记录，不为每个对象重造治理

L2 · 只需留下三样

  1. 固定题集：原始输入、参考及可追溯的来源。
  2. 逐题结果：预测、指标，适用时保存判词和失败状态。
  3. 每轮记录：对象版本、题集、改了什么、结果如何；实际做过的归因连到对应错题。

L3 · 只守三条

  1. 版本用同一份题比较；开发题与回归题分开。
  2. 参考答案不进入被优化对象的推理输入；调用失败不删题冒充改善。
  3. 文本判官先用少量人工确认样本核对，再据它优化；具体方案尚未设计。

不默认建设独立审批流、身份服务、逐 gate 台账或多重判官。失败记录是避免误读结果所需的信息，不是新的优化 KPI。

后续迭代顺序

定原始数据与题集→准入 / 评分 / 富化各自拟合→固定分数调精选规则→相同题集回归

后续接入时确保被测输出就是拟交给用户的字段与成员；这是四个对象自身的边界，不恢复一个重复计分的 O5。
