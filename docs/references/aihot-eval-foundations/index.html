以用户看到的内容为终点

用同一时间段、共同来源的过滤前新闻，逐条拟合 AIHOT 的页面输出。组件评测用于归因，完整页面结果用于验收。

本报告按既有前置定义展开设计；未选定的判官模型、尚未形成的校验方案与阈值会明确留空，不用旧实验成绩补齐。

L1 · 怎样算

对象、题目、判官、自动指标、判官校验。先知道每个数字到底衡量什么。

L2 · 留下什么

L3 · 何时可信

控制身份、可比性、评价来源、采信与归因准入，不把缺测当通过。

02

原始数据：宁少，不混、不补造

输入：AI RADAR 过滤前归档

保留共同来源的全量候选，包括后来被过滤的新闻。以采集时实际取得的文章版本及原始证据为准，不从可变业务库倒推历史输入。

目标：AIHOT 网站实际可见输出

同窗口的页面捕获，以及支撑页面解释的 API / SSR 证据。参考输出是页面呈现，不是 API 中所有存在的字段。

9/06—9/13 是期望范围，不是可用数据结论。UTC+8，含首尾 8 天 / 192 小时，对应 [2026-09-06 00:00, 2026-09-14 00:00)。实际完整连续窗口、来源数、新闻数、可用题数尚未核定。本报告不重新审计当前库存。

准入面拟采用的规则不能据此推断
共同来源同窗至少有一次 AIHOT 出现证据，并核对来源入口与语义映射；无证据来源隔离待核。未见过 ≠ AIHOT 永不采集；不能只留 URL 交集。
连续性逐来源 × 采集时槽核对成功、成功空、失败、缺失；304 必须能追溯依赖内容。有新闻的日期 ≠ 全天采集完整；不拼接断续窗口。
文章配对URL + 来源身份 + 内容版本 + 实际可用时间；分别保存发布时间、归窗时间与观察时间。同 URL ≠ 同输入；AIHOT 内部输入等价性可仍未核实。
参照状态明确区分值已知、明确为空、页面隐藏、尚未捕获；缺失参照不填默认值。AIHOT 未展示 ≠ prefilter 负例；看不到 tags ≠ tags=[]。
排除范围T5 旧实验、旧评测 runs，以及微信专用源 / 独有 /wechat 解读、interpret、知识库。不按微信域名一刀切；共享新闻源里的微信原文仍可准入。网站所需数据继续保留。
分组与历史按真实使用历史划分开发、回归和真正未接触集；同事件、转载与文章版本不跨组。反复看过的历史题不能改名 holdout。精选需初始归档状态与 warm-up。
来源 / 窗口准入→保留完整 raw 候选池→配对 AIHOT 页面参照→按对象派生题集

AIHOT 有、Radar 原始归档没有的条目仍进覆盖缺口账；不能删除它们以后宣称总体召回更高。原始证据保持不变，各题集只是不同派生视图。

03

最终需要拟合什么

覆盖按用户看到的内容划分，不按内部模块划分。CSS 风格与独立性能优化不在本次范围；隐藏、截断、错误链接造成的内容差异在范围内。

维度AIHOT 参照内容直接归因 → 最终验证
D1 · 评分可见 AI 分数、分档 / 徽标、跨页面同条分值O2 → O4 / O5
D2 · 分类类别归属、分类后的条目集合O3 + O1 → O5
D3 · 标签标签具体集合、空集、显示与隐藏O3 → O5
D4 · 精选成员、数量、顺序、重复与归档O1–O3 → O4 → O5
D5 · 推荐理由事实依据、编辑角度、具体性与回退后文本O3 / O2 → O5
D6 · 新闻内容标题、摘要、实际展示的正文片段与附带文本O3 → O5
D7 · 普通列表收录、遗漏、额外条目、顺序及去重O1–O3 → O5
D8 · 事实身份来源、作者、时间、原文链接、媒体与相关信息归属主要确定性逻辑 → O5
D9 · 内容组织日报分组、热点等双方确有的共同面O5；共同面与参照覆盖待核
