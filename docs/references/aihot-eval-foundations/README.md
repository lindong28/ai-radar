## 目标与阅读入口

只拟合四类结果：“全部 AI 动态”收录哪些新闻、新闻的可见分数、分类/标签/标题/摘要/推荐理由，以及精选包含哪些新闻。不再另建最终可见端到端对象，也不把事实身份、内容组织、顺序或去重质量作为本次优化目标。

## 四个对象与拟合维度

| 对象 | 要拟合的结果 | 优化重点 | 指标 |
|---|---|---|---|
| O1 全部 AI 动态收录 | AIHOT 同窗共同来源的全部动态成员集合 | prefilter；实际影响收录的确定性规则也在对象内 | precision、recall |
| O2 评分 | AIHOT 已显示的新闻分数 | scorer 直接拟合；包含其后必要的确定性分值变换 | MAE |
| O3 内容富化 | 分类、标签、标题、摘要、推荐理由 | enrich；按五个字段分别建题和计分 | 类别 accuracy、标签 exact-set；文本 LLM judge 尚未设计 |
| O4 精选成员 | AIHOT 同窗共同来源的精选集合 | 固定已算出的分数，调阈值等选择规则 | precision、recall |

O1—O3 对应主要 LLM 组件；O4 使用它们的结果做确定性选择，不增加 LLM 判官。O3 按字段建题不意味着生产需要拆成五次调用。各对象直接承担自己的用户可见目标，不再靠一个独立总对象补齐。

## 数据边界

- 只用同一时间窗、共同来源的 Radar 过滤前 raw 和 AIHOT 可观察参考。共同来源须在该窗内至少有一次 AIHOT 出现证据，且来源入口语义相同。
- 共同来源的全部 Radar 过滤前新闻进入候选池，不先缩成两侧 URL 交集；同一新闻的重复抓取不重复计题。
- 排除 T5、旧评测 runs、Radar 独有的微信文章解读、interpret/KB 及微信专用来源；网站所需数据继续保留、正常采集。
- 不按微信公众号域名一刀切；来自共同主新闻源的微信原文仍可准入。
- 宁可少一些，也不接受污染、不完整或拼接成假的连续窗口。原期望 9/06—9/13 为 UTC+8 的 8 天、192 小时，不代表已经冻结成功。
- 没有 AIHOT 分数只从 O2 排除；其他对象仍按各自参考字段/集合取题。实际合格窗口和数量本轮未核定。

## 三层保持最小

L1 就是四个对象、各自题集及上表指标。只有标题、摘要、推荐理由需要 LLM judge；用少量用户核对的好坏样本确认它能分辨，再用于优化，具体方案尚未设计。

L2 共用固定题输入/参考，保存每题预测、指标及适用时的判词。L3 共用一条运行记录：对象版本、题集与结果；开发和回归分开，失败保留状态，不删除失败题，也不把失败伪装成空集满分。不为每个对象重复建设一套治理系统。
