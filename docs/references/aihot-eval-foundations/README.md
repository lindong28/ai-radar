## 这组文档解决什么

目标是在同一时间段、共同来源的新闻上，让 AI Radar 的用户可见内容足够接近 AIHOT。参照物是 AIHOT 网站实际呈现，不是它的 API 中所有字段，也不是我方组件输出的分布比例。

这次先把“用什么数据、拟合什么、优化哪几个对象、如何出题和计分”写清楚，之后才逐对象建设 L1 计算逻辑、L2 数据资产与 L3 治理，再实施离线评测、复盘、归因和优化。本文没有替这些后续步骤宣告完成或预先批准阈值、费用与模型。

## 用户边界

- 仅评测 AIHOT 与 AI Radar 共有的新闻内容面；不评测 Radar 独有的 `/wechat` 微信文章解读、`interpret`、知识库或微信专用来源数据。
- 排除的是用途和来源身份，不是 `mp.weixin.qq.com` 域名；共享主新闻源包含的微信公众号原文仍按同一套证据准入。
- 网站需要的微信数据继续保留并正常采集；评测子集筛选不等于修改生产采集范围。
- 不使用 T5 旧实验或旧评测 runs 作为新原始输入或 gold。原始数据宁少勿污染、勿伪装连续完整。
- 原期望窗口是 UTC+8 的 9/06—9/13，含首尾共 8 天、192 小时；它不是已经存在的完整冻结集。实际可用连续子窗仍须核定。
- 不用当前可变业务数据库补造过去未留档的输入，不把仅 URL 相交的一小批新闻说成共同来源的完整候选池。
- 本次内容对齐不包含 CSS、像素风格或性能的独立优化；字段隐藏、摘要截断、链接跳错等影响读者所得内容的差异仍在范围内。

## 最终拟合维度与对象覆盖

下表中的“负责”表示后续题集必须覆盖，不表示已经取得该面的完整 AIHOT 参照。共同的日报/热点等面仍须实测确认；未核实不等于不存在或自动排除。

| ID | AIHOT 网站的目标维度 | 直接组件归因 | 组合对象与最终验收 |
|---|---|---|---|
| D1 | 每条新闻可见 AI 评分、分档/徽标及同条新闻跨页面的分值 | O2 评分 | O4 选择后变换；O5 最终显示分 |
| D2 | 新闻类别、类别归属与分类后的可见条目 | O3 类别输出 | O1 准入影响集合；O5 分类投影/筛选 |
| D3 | 可见标签的具体集合、缺失/空集及显示位置 | O3 标签输出 | O5 二次投影、隐藏与回退 |
| D4 | 哪些新闻进入精选、精选集合、顺序与重复 | O1、O2、O3 提供输入 | O4 整池精选/归档；O5 实际列表 |
| D5 | 精选推荐理由的事实、依据、角度与具体性 | O3 推荐理由；O2 reasoning 可为回退 | O4 状态；O5 覆盖/回退后的理由 |
| D6 | 每条新闻的标题、摘要及网站实际可见的正文片段 | O3 标题/摘要 | O5 原文回退、裁剪、媒体附带文本与可见范围 |
| D7 | 普通新闻列表的收录、遗漏、额外条目、顺序及去重 | O1 准入；O2 相关性；O3 类别 | O5 真实页面与路由；O4 提供精选状态 |
| D8 | 来源、作者、发布时间、原文链接、媒体与相关信息的正确归属 | 主要非 LLM 产出，O3 不得改变事实身份 | O5 确定性投影与链接身份回归 |
| D9 | 日报分组、热点等双方确有的内容组织面 | 依赖所消费的 O1—O3 结果 | O5 纳入已确认共享面；参照覆盖待核 |

以上九个维度以内容结果组织，不要求 AI Radar 复制 AIHOT 的内部算法。D8/D9 中的确定性逻辑走普通回归，不为每个字段虚构一个 LLM 对象。某一页没有展示标签时，目标是该页的可见性一致，而不是强迫两侧都显示全部标签。

## 五个对象，三类直接调用

O1 是新闻准入组件；O2 是评分组件；O3 是 enrich-v2 内容富化的联合组件，含分类、标签、标题、摘要、推荐理由。O4 是由这些输出驱动的精选组合 workflow，包含确定性的排序、去重与累积归档；O5 是整个新闻内容链到真实页面的端到端对象。

O4/O5 不是新增两次 LLM 调用，也不是五个互不相干的分数。组件题帮助定位差异，组合题检验阶段衔接与历史状态，最终以 O5 的用户可见结果回答是否接近 AIHOT；不能把五个分数重复加总。

源码入口依次为 [prefilter](../../../src/airadar/prefilter/runner.py)、[scorer](../../../src/airadar/scorer/runner.py)、[enrich-v2](../../../src/airadar/enrich/runner_v2.py)、[curator](../../../src/airadar/curator/select.py)、[presentation](../../../src/airadar/presentation/summary.py) 与 [前端](../../../web/static/app.js)。源码核对基线为本地 `f0b4db0`；不据此声称生产部署身份已重新验证。

旧 [eval-fit runner](../../../src/airadar/eval/aihot_fit/run.py) 明记 `stage_gating=none`：逐题强制运行各组件，不复现生产准入、精选归档或浏览器输出。可以复用已核实的局部实现，但旧成功成绩不能代替 O4/O5。
