# 四个评测对象、指标与建题方法

> [Developer] · Mutable snapshot · 2026-09-16 · 按用户反馈简化；本轮仅改设计，不冻结数据、不运行评测。数据准入见 [raw-data](raw-data.md)。

## 共用约定

只保留下述指标，不设额外总分或错误率 KPI。各对象固定题输入和参考，运行时只提供输入，不把参考答案传给被优化对象。没有相应参考的新闻不进入该字段题集，但不影响其他题集。

按唯一新闻集合计算成员指标，重复抓取不重复计数。分母为 0 时为 N/A，不记满分。调用失败保留题和失败状态；不能偷偷删题，也不能当作成功空输出。不确定如何给失败计数时报告该轮结果不完整，不从成功子集推出全题集达标。

## O1 · 全部 AI 动态收录

**拟合目标与优化对象。** 只看 AIHOT“全部 AI 动态”收录了哪些新闻。重点优化 [prefilter](../../../src/airadar/prefilter/runner.py)，同时包含实际影响我方收录结果的确定性规则。当前 [timeline](../../../src/airadar/web/routes/timeline.py) 除 prefilter 外还有 relevance 阈值；不能只测 prefilter 返回 true，就称为实际已收录。

**输入/输出与建题。** U 为同一连续窗口、共同来源的全部 Radar 过滤前新闻输入；R 为完整 AIHOT“全部 AI 动态”在同一范围内的新闻身份集合；C 为 Radar 在该范围实际准入的新闻集合。对 U 中每条新闻用“是否属于 R”建参考标签，运行后汇总 C。

未在完整 R 出现的 U 新闻可标 0，含义仅为 AIHOT 未收录，不是客观非 AI。R 不完整时先补足参照或缩到完整窗，不能把漏捕获当 0。

| 指标 | 计算 | 方向 |
|---|---|---|
| precision | `|C∩R| / |C|` | 越高越好 |
| recall | `|C∩R| / |R|` | 越高越好 |

AIHOT 有而 Radar 缺 raw 的新闻保留在 R，也就是保留在 recall 总体分母，旁列缺输入数；不要让 prefilter 优化背负无法处理缺输入的假任务。这里不增加精选正例子集、排序、去重质量、全池放行率或逐 gate 统计。

## O2 · 可见评分

**拟合目标与优化对象。** 优化 [scorer](../../../src/airadar/scorer/runner.py)，直接拟合 AIHOT 网站可见分数。当前 [schema](../../../src/airadar/scorer/schema.py) 的内部维度不是本次参考真值；只比较最后要交给用户的数值。

**输入/输出与建题。** 只选“AIHOT 有可见数值分数＋有可配对 Radar raw”的新闻；每题输入是固定 raw，参考是该条可见分数。候选预测取 scorer 经必要确定性分值变换后将展示的分数，与参考统一量纲。没有分数的新闻只从本题集排除。

**唯一指标。** `MAE = Σ|预测分−参考分| / N`，越低越好；N 为固定评分题数。失败题不填 0 分，也不删除；有失败时完整题集 MAE 未完成，可附成功题的误差供诊断但不能称为完整成绩。

当前 [select.py](../../../src/airadar/curator/select.py) 的 `rank_linear_v1` 会按入选排名改分，[app.js](../../../web/static/app.js) 会把 weighted_score 乘 10 后取整。因此 O2 包含 scorer 后必要的确定性分值变换：后续实现需让拟合分真正成为展示分，不能 raw 拟合好了又被排名映射覆盖。这是对象边界，不是本轮已经修改生产规则。

## O3 · 分类、标签与文本富化

**优化对象。** 现有 [enrich-v2](../../../src/airadar/enrich/runner_v2.py) 联合生成多个字段，仍可保持联合调用；评测按字段分别建题。每类题都要求“有该字段可观察 AIHOT 参考＋有可配对 Radar raw”，不要求一条新闻同时具备五种参考。

| 字段题集 | 输入与参考 | 指标/判官 |
|---|---|---|
| 分类 | raw → AIHOT 可见类别 | accuracy：正确题数 / 分类题数，越高越好 |
| 标签 | raw → AIHOT 可观察标签集合 | exact-set：集合完全一致题数 / 标签题数，越高越好 |
| 标题 | raw → AIHOT 可见标题 | LLM judge，尚未设计 |
| 摘要 | raw → AIHOT 可见摘要 | LLM judge，尚未设计 |
| 推荐理由 | raw → AIHOT 可见推荐理由 | LLM judge，尚未设计 |

分类先固定两侧类别的对应关系；明确“未分类”与未知分开，不能把未知填成某个类别。标签集合不比较顺序，不先删除我方多余标签来制造一致；参考明确为空且候选成功返回空集时可算一致，未知参考不入题。候选失败/字段缺失算不一致，即使参考为空也不能得分。

拟合的是用户看到的字段值，必要的 [normalizer](../../../src/airadar/enrich/normalizers/production_enrich_provider_output_v2.py) 和 [presentation](../../../src/airadar/presentation/summary.py) 转换属于该字段的输出路径，不另设一个总评测对象，也不把字段可见性本身新增为 KPI。

文本判官的任务是判断候选与该条 AIHOT 参考是否足够接近，同时读原始输入避免奖励编造；模型、prompt、量表、样本数、阈值和最终指标形式均尚未设计。只保留最小校验：请用户核对一小批好/坏样本，再检查判官能否正确区分；通过前不拿它的分数决定优化方向。不用字符重合替代这一判断。

## O4 · 精选成员选择

**拟合目标与优化对象。** 只比较固定时间窗内精选包含哪些新闻。评分完成后固定候选池及分数，调 [curator](../../../src/airadar/curator/select.py) 的阈值等选择规则；不增加 LLM 判官，也不评价精选顺序或去重质量。

**输入/输出与建题。** 一题是同窗共同来源的完整候选池及已算分数，参考是 AIHOT 同范围的完整精选集合。不能只用 AIHOT 已精选的新闻做候选，也不能按参考精选数直接取同样数量来冒充选择规则。若使用累积归档，固定明确的初态作为输入即可；本次不复刻 AIHOT 内部运行，不要求重建全部生产历史。

令 R 为完整 AIHOT 精选参考集合，C 为我方规则选出的成员集合。只计算 `precision=|C∩R|/|C|`、`recall=|C∩R|/|R|`，越高越好，零分母 N/A。参考中缺 Radar raw 的新闻仍在 recall 分母，另列缺输入数；参照不完整时不宣称算出了完整的精选拟合结果。

## 共用的最小 L1/L2/L3

**L1。** O1/O4 用集合 precision/recall；O2 用 MAE；O3 分类和标签用确定性比较，三类文本使用待设计并经最小样本核对的 LLM judge。题目按上文构造，不再扩指标。

**L2。** 固定每道题的输入与参考，保存预测、指标和适用时的判词。四个对象共用这套记录，不重复建设多套资产分类。

**L3。** 每次运行只记录对象版本、题集和结果；开发/回归分开，失败不删题，判官未校验不用于优化。本轮尚未指定实际题量、文本判官方案或达标阈值，也没有运行成绩。
