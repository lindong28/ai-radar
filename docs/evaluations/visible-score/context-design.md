## 顺序与可证伪实验

| 顺序 | 只改变什么 | 对照及差异预测 | 采用或停止条件 |
| --- | --- | --- | --- |
| S1 来源身份 | A11 增加冻结本地来源名称、来源类型、账号/站点身份；不改原始 tier 或 gold | 同一开发 200 题、同 Flash、同五维和权重。若身份不足是原因，authority 及相应残差应改善；若只是标签重述，总误差不应稳定下降 | 记录各来源组配对误差，不能由异质组均值认定因果；失败也保留 |
| S2 条件组合 | 在相同已存维度上，用少数有语义的来源/文章类型条件调整组合；与全局权重直接比较 | 保留五维、正权重和 0–100 范围，不加截距、来源 ID 偏置、目标分数或人工示例。所有条件来自输入而非 AIHOT 输出 | 开发内部留出检验，条件和权重冻结后才看回归；开发收益不外推泛化 |
| S3 时效 | 只在时间语义可证的子集加入观察时刻与发布时间间隔 | 同题有/无时效。若是旧闻惩罚，应主要改变旧闻残差，而非全体统一降分 | 不使用当前机器时钟；无法确定首次可见时间的题不混入；小样本只能诊断 |
| S4 事件上下文 | 将当时可获得的同事件报道放进上下文，与单条评分和权威主报道选择分别比较 | 先检验“选更完整/权威报道足够”再检验“聚合事实或独立报道量还带来收益”；转载量不等于独立证据数 | 禁止未来报道和 AIHOT 分数/精选/生成摘要进入输入；无法恢复当时池子的窗不宣称整窗实验。输入单位改变时另建 benchmark，不覆盖 pointwise/v1 |

S1/S2 是最低成本方向，不增每条生产网络请求。S3/S4 引入的生产复杂度仅在离线收益明确后再讨论，不因实验可运行自动上线。公司信息以报道中的角色/行动解释，不按公司名字记忆目标分数。源身份和该条内容是否一手是两件事：官方账号也会转载，个人也能发布自己的原始实验。

## 时间和事件的防误读

`aihot-original-detail` 输入的 fetched_at 由参照 capture.finished_at 派生，是归档观察时间，不是 AIHOT 首次采入时间。Radar 的可变 items.fetched_at 会随重复抓取更新，不是 first_seen。只能从冻结逐轮档案建立“本归档覆盖内首次见到”的时间，并注明左截断；published_at 的日期 fallback 不冒充精确时刻。AIHOT API 的 discoveredAt 是参照侧时间，须核实语义，不能直接当作 Radar 的可用输入。

事件池要保存 as_of、窗口边界、每条输入当时可用的证据和选代表规则。相同事件/引用材料不得跨开发与未见验证。AIHOT 的聚合成员可以作单独 oracle 诊断或聚类参照，不能作为我方推理输入后声称无泄漏。正文缺失、同事件识别错误、代表选择错误、评分错误分别归因。

## 复用和报告

沿 [执行入口](../../../evals/visible-score/aihot-score-pointwise/README.md) 和 [资产约定](../assets.md) 冻结 prompt/config/source hashes、实际题 ID、原始响应 reason、五维、失败 attempt、MAE/Spearman 和调用量。同题复用旧响应是零调用重放，不伪称新推理。开发集用于归因，旧回归 100 题已经曝光，只能叫已见回归；候选在开发侧不足时不消耗新的未见题。冻结后验证须同时给两指标及分母，Spearman 没有另设用户未要求的硬阈值。

不自动改 gold 或删除“大残差”题；实际人票按 [人评规则](../human-labels.md) 优先。当前评分资格复核页尚未收到实际票。每轮 conclusion 记录假设、基线、改变、结果、归因、是否采用和下一步；未知不记成失败，更不记成 0。原始文章、时间和上下文证据与标签隔离保存。
