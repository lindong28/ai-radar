# 新闻准入：时间标注修订设计（已批准）

> [Developer] · 2026-09-19 · 用户随后明确批准“继续修改 gold 和重建题库。记得更新文档。然后继续对 precision 和 recall 进行优化”。实施入口为 [aihot-observed-membership/v1](aihot-observed-membership/v1/README.md)，实际进度和读数见 [status](status.md)。此前仅出版的边界保留在 [ADR](../../adr/20260919-9365-publish-admission-time-label-proposal.md)，不再阻止本次已授权实施；模型调用仍遵守剩余预算。

## 1. 拟议目标：评准入，不把收录延迟当作拒收

输入仍为给定采集范围内、共同来源的 Radar 未过滤新闻；参考答案改为**在冻结的 AIHOT 原始参照批次中，是否观察到同一新闻被收录**。同来源、规范 URL、实质内容身份成立后，不再因时间差超过 ±12h 否决已有收录证据。

这不是“AIHOT 显式判它应收／不应收”，也不是“AIHOT 永远会不会收”。网站只提供已展示成员，没有其私有候选池与拒绝记录。指标仍只用 precision、recall，不加 LLM 判官；两项分别 >90% 的目标不变。

## 2. 为什么需要修订

以下均来自已见第三批回归，时间为 UTC；每条在其覆盖参照的两遍原始 API 中都有同身份记录。不能把这 3 条的情况外推成全库错误比例。

| 案例 / case_id 前缀 | Radar 用来匹配的时间 | AIHOT 记录 | 旧规则结果 |
| --- | --- | --- | --- |
| OpenRouter In-Region Routing / `6424534c` | 9/09 00:00 | 9/09 14:27:50 发现 | 超过 12h，负例 |
| Claude 开发者版本说明 / `6e137468` | 9/03 00:00 | 9/04 18:50:19 发现 | 超过 12h，负例 |
| HF E2A-Bench / `69c0d033` | 9/15 14:50:07 | 9/13 00:00 已有记录 | 抓取时补填的时间与参照错位，负例 |

原始审计：[error-raw-reference-audit.json](../../../runs/news-admission/aihot-prefilter/v1/2026-09-19/12-50-00/error-raw-reference-audit.json)。其中另 3 条 FP 在各自覆盖参照中未匹配，不代表 AIHOT 从未收录。

当前实现的两个语义不同：[`AdmissionIndex.label`](../../../evals/_shared/object_datasets.py) 以 Radar `published_at`（无则 `fetched_at`）±12h 取匹配；[`timeline_key`](../../../src/airadar/eval/aihot_dataset.py) 通常取 AIHOT 发现时间，但当发现比发布时间晚超过 72h 时改取发布时间。它不是统一的原文时间轴。[Web 采集器](../../../src/airadar/fetcher/web.py) 的 `_parse_papers` 不提供发布日期，`_date` 在日期非必填且缺失时返回 `utc_now()`。因此字段非空不等于知道了原文发布时间。

## 3. 时间各司其职

| 时间 / 范围 | 用途 | 不得用来做什么 |
| --- | --- | --- |
| 原文发布时间 P | 有来源证据时，用其最早可能时点界定需要核查的历史范围；只有日期时保留日期精度与时区 | 不把抓取时补填值当真实发布时刻，不靠字段名或两个时间相等推断 provenance |
| Radar 实际抓取时间 | 选择候选采集范围、证明输入实际可得；保留首次取得的原始输入与后续补采记录 | 不倒填为更早已取得，不把重复抓取当新题 |
| AIHOT 发现时间 | 描述 AIHOT 记录与收录延迟；保留原值 | 不作为同新闻身份的 ±12h 否决门，不冒充我方实际观测时刻 |
| AIHOT 归档实际采集时间、冻结截止 C | 固定这版允许使用哪些已完成参照批次 | C 不是网站某一瞬间的完整快照时刻；C 之后新证据不混入旧版 |
| 每批可证完整覆盖范围及共同右界 H | 判断负例所需的历史是否已覆盖；候选实际到达不得晚于所用 H | 遍历完成时间不等于 H；不能声称 `[H,C]` 完整 |

复用原始记录及现有 provenance；缺失含义留为未知，不改写 raw。先固定候选采集区间和证据批次，再看标签；不能为得到更好的分数给不同题挑不同截止。

## 4. 最小建题规则

### 先定候选与主集资格，再标正负

候选只来自 Radar 真实未过滤输入及冻结的共同来源合同，沿用“合并＋规范身份去重＋按实质内容检查有效性”。不添加 AIHOT-only 正例；不以模型输出、新闻主题或已知 gold 选择候选。仅发布时间、HTML、标题标点、来源显示标签变化，不作为实质版本冲突。

主集资格对正负一视同仁：来源身份清楚、输入有效、所需参考历史已完整覆盖且末两遍成员稳定。可靠 P 到 H 可界定核查范围；必须先证明 AIHOT 查询窗口、分页链和时间语义确实覆盖这个范围，不能直接把旧 ±12h 覆盖检查换参数就视为证明。仅 `has_more=false` 不能证明没有查询范围之外的历史；仅首尾新闻时间也不能证明中间完整。未知 P 时，只有另有**不依赖匹配结果**的历史边界证据才可取得同等资格，否则不进主集。不能用仅正例才有的 AIHOT 匹配记录补 P，让正例单独取得资格。

这是按实际数据充分性建题，不要求每一采集轮都成功；补采能提供所需输入与参照时可用，不能据补采成功宣称过去每一时刻完整。末两遍稳定只说明该批次稳定，不保证未来不会迟到。

### 标签与去向

| 已冻结证据 | 去向与参考输出 |
| --- | --- |
| 主集资格成立；任一允许的原始参照中已有同来源、规范 URL 且无实质版本冲突的收录证据 | 主集正例 `member=true`，不受 ±12h 限制；历史已见证据不被较晚投影中的缺席抵消 |
| 主集资格成立；完整检查冻结原始参照批次后未见收录 | 主集负例 `member=false`，含义仅为**在这些批次未观察到收录**，不是“截至 C 瞬时未收录”、显式拒收或永不收录 |
| 主集资格不足，但已有可靠同身份收录证据 | 仅召回补充集，不并入主集 precision 或双90验收 |
| 主集资格不足且未匹配，或存在无法消解的来源／实质版本冲突 | 未知／排除，保留原因，不当负例 |

正例见证查完整原始 API，而非仅日窗 `items.jsonl` 投影。不能因投影中没有，就把原始 API 中已有的记录判不存在。无法确认两条 URL 实质同一时不模糊合并；不自动跨来源转正。

上面 3 条旧负例将不再因“窗外”而维持负例；是否能进**主集正例**仍须同等资格检查。尤其 HF 缺真实发布时间，不能因刚好找到一个正例就跳过这道检查。资格不足的正例只能进入仅召回集。

## 5. 三层如何接续

| 层 | 本次设计改什么 / 复用什么 |
| --- | --- |
| L1 | 仅变更②参考语义及准入规则；①仍是原始输入→prefilter，③⑤无模型判官，④仍为 `TP/(TP+FP)` 与 `TP/(TP+FN)`。失败响应不作 false、不删分母。 |
| L2 | 批次、raw、逐题输入、规范身份、标签证据与迁移去向可追溯；复用既有 builder／runner／scorer／归档链，不复制另一套系统。批准实施后才生成新题库与迁移统计。 |
| L3 | 新语义与旧语义分开；候选和主集资格标签盲，输入与参考隔离；冻结截止不等于瞬时完整；旧实验不可改名充当新实验，改 gold 带来的分数变化不称模型优化。 |

消费者必须重新理解 `member=false`，故使用新 benchmark **`news-admission/aihot-observed-membership/v1`**，而非旧 benchmark 的 v2。未来相同语义扩数据再递增 v2/v3；每版仍是完整去重快照。旧 `aihot-prefilter/v1` 保留供复现，不累计题数或混合成绩。建题显式指定 `--admission-benchmark aihot-observed-membership`；共享脚本的历史默认值不静默改义。

## 6. 已批准的实施与验证范围

1. 在共享建题实现中加入新标注方式、日期 provenance 与覆盖资格判断；新 benchmark 叶子复用既有执行和评分组件。同步项目入口、建题／扩展命令与新版本说明，旧入口仍可复现旧语义。
2. **先零调用建题审计**：对选定全部原始候选按同一规则重验，不只修已见错误。列出主集正／负、仅召回、未知，以及旧→新标签和去向变化，按来源列覆盖损失；不能先许诺原 11,804 题都能留下。数据仍放 `~/research/video-eval-arena/data/benchmarks/ai-radar/news-admission/`，不上 DGX。
3. 验证本节规则的两侧：窗外同身份收录、无见证但覆盖充分、无见证且覆盖不足、日期 fallback、不同来源、真正内容冲突、投影缺席但原 API 存在。并证明主集资格不随 gold 或模型预测变化。
4. 只有被测配置和实际模型输入完全一致时复用旧响应，在新 benchmark 下重新计分并保留来源；缺失响应继续缺失。旧/new gold 的重评分只用于量具诊断，不作为优化收益。
5. 后续恢复模型优化时，在新题库上建立同题基线与候选对照。此前已查看的 1,200 条回归题继续标为已见，不能换 benchmark 名后重新宣称未见留出。新增付费运行另按范围和预算批准，不由本设计自动启动。

## 7. 明确的代价与尚未解决的边界

合格主集可能变少、来源分布可能变化；标签盲筛选能避免“只补正例”，但**不能保证留下的子集代表全部来源**。应随新库存给出覆盖范围，precision/recall 只外推到对应总体。

本设计不把时间问题包装成全部根因：`buzzing_hn` 聚合子流与 AIHOT 实际输入范围是否一致仍有未验证部分；沿用冻结来源合同不等于证明私有 feed 一致。仅改时间标签不解决来源错配、真正内容误判或供应商拒答，也不保证双90。未来迟到／新证据造成标签变化时发布新快照，不改旧版；不凭空规定 48h/72h 成熟期。

实施结果由 [status](status.md) 和新版本 manifest 给出，包括题量、来源覆盖与重评分；迟到分布与 AIHOT 私有拒收规则仍不由本设计推定。未拿到原文时间证据的 raw 继续保存，不能为保住题数放宽资格。
