## 产品概述

**产品形态**：公开只读 Web 应用，部署在 `https://aiplanet.live`

**使用者**：工程师（单人维护 + 公开浏览），日常用于 AI 领域信息消费——每天快速浏览精选内容掌握 AI 动态，需要时通过时间线和搜索深入某个方向。

**使用方式**：
- **日常浏览**（~5 分钟）：打开精选页，扫标题和推荐理由，点感兴趣的去原文
- **深度探索**（按需）：切到时间线页，用信源类型/分类/搜索筛选，逐页浏览
- **回顾查阅**（按需）：日报页按日期查看历史精选汇总
- **微信文章解读**（按需）：切到微信文章解读页，扫精选的微信公众号文章卡片（标题+摘要+标签），点开读完整的结构化解读

**核心价值**：从 40+ 个信源中自动筛选高价值 AI 资讯，通过评分 + 规则过滤实现"精度 ≫ 召回"——每天精选约 30-40 条（vs. 原始时间线数百条），降低信息噪音。

## 页面与功能

### 精选页（`/`，首页）

产品的核心入口，是所有曾被 AI 选入精选的高价值内容的**累积归档**——把历次精选（每轮 top-40）选出的不同条目去重汇总，按发布时间从新到旧**无限滚动**浏览（首屏即最新精选，覆盖"5 分钟扫一遍"的日常用法）。

**页头**：不包在卡片里，标题直接落在页面底色上。副标题带日期前缀，取**当前列表中最新一条内容**的发布日期（Asia/Shanghai，中文长日期），每次筛选 / 搜索 / 刷新后同步更新；列表为空时不显示日期前缀。

**内容卡片包含**：
- 信源图标 + 信源名称
- 中文标题
- 中文摘要
- 推荐理由（解释为什么这条值得看）
- "精选"标记：渲染为来源行内、紧跟来源链接之后的 chip（`✦ 精选`，琥珀色字 + 淡琥珀底 + 小圆角），不与分数并排
- 分数标签：独立位于卡片右上（数字分数，颜色编码：≥80 高分、65-79 中等、<65 低调）
- 媒体资产（文章配图，可点击查看原图）
- 关联讨论（同一事件在其他信源的报道数量，悬停可查看信源列表）
- 发布时间
- 点击标题 → 在新标签页打开原文

**首页不显示话题标签**。主信息流中标签只在时间线页（`/all`）呈现，带 `#` 前缀；标签文字本身与输入数据逐字相等（前缀不进入可复制文本）。收藏页与微信解读页的标签不受此条约束。

**桌面时间线的连接关系**：同一日期分组内，一条连续竖线贯穿该组全部条目的圆点（不在条目之间断开）；日期分组折叠后该线不残留。条目被收藏时，该条圆点转为琥珀色强调。

**日期分组头（桌面）**：日期右对齐，与该组下方所有时间戳共一条右边界；星期与条数排在日期右侧的内容区。可折叠，折叠态在追加加载新批次后继承。

**筛选功能**：
- 分类筛选：模型 / 产品 / 行业 / 论文 / 技巧（5 个分类）
- 搜索：匹配标题、正文、来源名、作者和中文标题；3 字及以上走全文搜索，1-2 字在短字段（标题/来源名/作者/中文标题）中兜底匹配
- 搜索有 `q` 时，来源名 / 作者命中的条目在入选层面优先于仅标题 / 正文 / 中文标题命中的条目；同一命中层内按 `source_id` 轮转，使每个匹配来源的首条内容优先进入首批；无 `q` 时保留原发布时间倒序
- 浏览方式：**无限滚动**（滚到底自动追加下一批），按发布时间倒序，每批约 40 条；追加按唯一条目 key 去重，任何时刻不出现重复卡片。数据集稳定（滚动期间无采集写入）时，terminal 唯一条目数**精确等于** API 报告总量——无限滚动不牺牲归档完整性；滚动期间发生采集写入时仍保证无重复，期间新增条目在刷新后可见、总量以刷新后的新代际收敛
- 服务端直出的首屏条目数与客户端首批一致，因此首屏不会在加载完成后被整批替换，也不因该交接产生可见的内容跳动
- 用户感知性能（same-host provisional）：首页首张卡片可读旅程 P75 ≤2s、P95 ≤3s；由部署主机的 origin/public 浏览器探针持续覆盖，不代表 East Asia 或其他区域 SLO

**热点模块**：
- 固定显示 `GET /api/v1/hot?limit=2` 返回的前 2 条（响应不足 2 条时与实际数一致）
- 标题：桌面「当前热点」，≤960px「今日热点」
- 标题行右侧有「完整榜单 →」，跳转 `/hot`
- 名次配色四档（第 1/2/3 名各自配色，其余同一档）；榜单行分隔线贯穿卡片内宽

### 时间线页（`/all`）

完整的按时间排列的内容流，用于深度浏览和探索。

**内容卡片**：与精选页类似——所有条目显示分数标签，被精选的条目额外显示"精选"标记和推荐理由。

**卡片标签**：话题标签渲染为井号前缀的弱化文字（`#其他`、`#具身智能`），不是带边框的药丸 chip。

**筛选功能**：
- 分类筛选：同精选页（5 个分类），渲染为**一行**分类 tab
- 信源类型筛选：全部 / 一手信源（官方源）/ 资讯 / 推文（3+1 选项），收进**下拉**（不再与分类并列成第二行 tab）
- 搜索：同精选页，匹配标题、正文、来源名、作者和中文标题
- 搜索排序/入选规则同精选页：有 `q` 时来源名 / 作者命中优先，同一命中层内按 `source_id` 轮转；无 `q` 时保留原发布时间倒序
- 浏览方式：**无限滚动**（每批约 40 条，追加按唯一条目 key 去重，任何时刻无重复卡片）。数据集稳定时 terminal 唯一条目数精确等于 API 报告总量；滚动期间发生采集写入时仍无重复、刷新后收敛。快速切换查询时最终列表只属于最后一代请求
- **例外：搜索态（有 `q`）仍使用 page 分页**——timeline API 在搜索时忽略 cursor，这是既有实现约束下的有意取舍，不是遗漏

### 热点榜页（`/hot`）

近 48 小时的热点榜单，桌面侧栏「内容」分组可达，移动端从首页「完整榜单 →」进入。

**页面结构**：
- 渲染 `GET /api/v1/hot?limit=10` 的全部响应项，DOM 的数量、顺序、名次、标题、原文链接、热度值与主信源与 API 逐项一致
- 每行：名次（1/2/3 三档配色 + 其余一档）、标题（点击直接打开**原文**，不是站内聚合页）、主信源、相对时间、热度值
- 相对时间基于响应的 `event_time` 计算：取可解析且不晚于 `generated_at` 的 `published_at`，否则回退 `fetched_at`
- 关联信源展开：**仅当该条目实际有关联讨论时**才渲染可展开控件，列出主信源 + 全部实际关联信源并去重；无数据时不渲染展开控件，不伪造条目
- 方法说明：写明响应级的「过去 48 小时」与本站公式「加权分×10 + 关联讨论×5」
- 空榜单时显示显式空状态

**明确不提供**（数据模型无对应概念）：「爆 / 新 / 发酵中」状态标签、24 小时趋势线、「氛围票」、站内聚合 story 页。

### 日报页（`/daily`）

按日期组织的精选内容归档，浅色、与全站同一套设计 token。

**页面结构**：
- 归档侧栏：按**月份分组、可折叠**的归档列表（月份行带该月期数，展开后列出该月每期），底部有「全部日报 →」。显示的月份数、各月期数与日期集合与可用日报全集一致
- 日期导航：← 前一日 / 后一日 → 箭头按钮
- 报头：上方小标 `VOL.<YYYY.MM.DD> · <N> STORIES · AI RADAR DAILY`，主标题 `AI RADAR 日报`，下方中文长日期。`VOL` 取当前有效日报日期，`N` 等于实际渲染的正文条目数
- 「今日看点」摘要卡：分类编号 + 标题 + 每类条数 + `N 篇报道 · 约 M 分钟`。`N` 等于实际正文条数、各类计数之和等于 `N`
- 章节头：`01 行业动态 INDUSTRY … 1 篇`（编号 + 中文名 + 英文小标 + 右侧计数）
- 主内容区：当天精选内容按分类分组展示
- **底部四项数据概览**：今日事件 / 一手报道 / 新模型 / 信源。桌面一行四格，≤960px 变为 2×2。该期无内容时容器隐藏、不显示空数字
- 正文摘要中的行内代码呈现为等宽字体的浅底 code pill

**四项数据概览的定义（本站自定，不声称与任何参考站一致）**：

| 格 | 定义 |
|---|---|
| 今日事件 | 该期正文实际条目数（与报头 `N STORIES` 的 `N` 相同） |
| 一手报道 | 该期中非推文类、且信源等级为 T1（一手信源）的条目数 |
| 新模型 | 该期中属「模型发布」分类的条目数 |
| 信源 | 该期去重信源数 |

**阅读时长公式（本站自定，不声称与任何参考站一致）**：`C` = 日报正文各摘要的可见中文字符数，只计 Unicode CJK Unified Ideographs（`U+3400–4DBF`、`U+4E00–9FFF`、`U+F900–FAFF`），排除标题、导航、元数据与章节标题；`M = max(1, ceil(C / 300))`，300 中文字符/分钟为保守整数常数。

**日期边界行为**：
- 非法、不可解析或**晚于今天**的日期：回退到最近一期并改写 URL，在报头附近显示**一行非警示色**的低强调内联状态文字（`role="status"`，包含实际回退日期）
- **合法但当天无内容**的日期：显示显式空状态，**不回退**、不改写 URL

**明确不提供**：日报 / 周报 / 月报三 tab —— 本站无周报月报数据管线，属功能缺失而非视觉差异。

### 收藏页（`/bookmarks`）

用户在卡片上点收藏后，条目进入本页。

- 收藏状态存于浏览器本地（localStorage 快照），不需要登录
- 支持导出 JSON 与再导入，导入经字段与日期可解析校验；导出后再导入的条目数一致
- 与全站同一套视觉 token，light / dark / 移动三态均可用

### 更新日志页（`/changelog`）

渲染仓库根 `CHANGELOG.md`，桌面侧栏「更多」分组可达，移动端从 `/more` 进入。

- 除下述两处**明确的渲染层增改**外，页面的有序内容块（标题、段落、列表项、代码）与链接目标，与 `CHANGELOG.md` 的解析结果逐项一致：（a）日期标题按固定规则本地化为中文长格式并附星期；（b）页面标题下方有一行源文件中不存在的固定引导语。条目顺序、非日期正文、代码与链接目标不作任何改写
- 当前页在侧栏高亮
- 日期头显示为中文长格式（`2026 年 8 月 4 日`，各段之间恰好一个空格）并附弱化的星期标签（`周二`），带下边框。`CHANGELOG.md` 源文件保持 ISO 形态不被改写
- 标题下方有一行引导语

**明确不提供**：侧栏「更新日志」项的未读红点 —— 需要未读状态持久化，属新功能而非视觉呈现。

### 更多页（`/more`）

**只在 ≤960px 有导航入口**（底部 tab 栏第 4 项），桌面无入口。

- 只收纳四个本站已有入口，href 精确指向：微信文章解读 `/wechat`、收藏 `/bookmarks`、关于 `/about`、更新日志 `/changelog`
- 不含主题、Agent 接入或反馈；不因新增页面而扩张

### 关于页（`/about`）

产品信息和透明度展示。

**内容**：
- 产品定位说明
- 信源池表格：列出所有信源的标识、名称、等级（T1/T1.5/T2）、状态、类型；表格上方有搜索框可过滤信源
- 评分维度解释：5 维评分（相关性、信息密度、时效性、权威性、工程价值）及权重
- 设计原则
- 致谢（项目引用和相关链接）
- 维护者联系方式 / GitHub 链接

### 微信文章解读页（`/wechat`）

独立 tab，展示来自订阅微信公众号的文章中"值得阅读"的那些，每篇配一份结构化解读。与主时间线/精选不同，这里点开是站内详情页（而非跳原文）。

**列表卡片包含**：
- 公众号头像 + 公众号名称（作者）
- 原文标题
- 摘要（文章概况首段）
- 受控词汇话题标签
- 发布时间
- 推荐等级徽标（必读 / 值得一看 / 可跳过）——与详情页"价值判断"模块的推荐等级一致
- 整张卡片可点击 → 站内解读详情页 `/wechat/<slug>`

**列表行为**：
- 展示进入"值得阅读列表"的文章，按发布时间从新到旧排列
- **收录口径偏召回**：每篇文章带一个**推荐等级**徽标（必读 / 值得一看 / 可跳过，列表卡片与详情页均显示）；由于偏召回，列表中**可能出现个别推荐等级为"可跳过"的文章**（它们有次级可参考价值）——这是产品有意的取舍，不是错误。"进入列表"与"推荐等级"是两个独立信号
- 搜索框 placeholder 为 `搜索标题/公众号/摘要/标签…`；匹配原文标题、公众号名（作者）、摘要（abstract）和标签（tags），不匹配正文、结构化解读全文、聚合 feed 来源名"微信公众号（Mp2RSS 合集）"
- 搜索一律使用 LIKE 匹配，不走 3 字及以上全文搜索分支；繁简互通，2 字专名可搜索
- 搜索有 `q` 时，公众号名（作者）命中的条目在入选层面优先于仅标题 / 摘要 / 标签命中的条目，其余按发布时间倒序；无 `q` 时保留发布时间倒序
- 搜索输入 debounce 后即时收敛结果，URL 同步 `?q=`，刷新/分享保留搜索态；清空搜索恢复完整列表；无匹配显示空状态
- 分页：底部数字页码分页控件——第 1 页与最后一页固定可见、当前页左右各 2 个相邻页、跳号处 … 省略、可点任一页码直接跳转、含上一页/下一页箭头（每页约 50 条）。**微信列表保留数字分页**，与已改为无限滚动的 `/`、`/all` 不同
- v1 无分类/信源筛选（WeChat 专属话题标签 ≠ 站点分类）；仅提供上述 WeChat 专属搜索
- 用户感知性能（same-host provisional）：列表首张卡片可读旅程 P75 ≤2s、P95 ≤3s；翻页内容稳定旅程 P75 ≤1s、P95 ≤1.5s；由部署主机的 origin/public 浏览器探针持续覆盖，不代表区域 SLO

### 解读详情页（`/wechat/<slug>`）

产品中唯一的站内条目详情页（其余页面点标题跳原文）。独立可分享 URL。

**展示**：
- "‹ 返回列表"链接（保留来源分页上下文）
- 原文标题、公众号名称 + 发布日期、话题标签
- 完整结构化解读，分模块呈现：文章概况 / 独特亮点 / 可动手实践 / 可复用认知 / 关键词 / 价值判断 等——**模块集合随文章而变**，部分文章含额外模块（如产品方向洞察）
- 可经标题/来源到达原文微信链接
- 用户感知性能（same-host provisional）：详情内容可读旅程 P75 ≤2s、P95 ≤3s；由部署主机的 origin/public 浏览器探针持续覆盖，不代表区域 SLO

### 条目跳转（点击标题）

精选页 / 时间线 / 日报的卡片：点击标题在新标签页直接打开原文链接，无站内详情页。**唯一例外**是微信文章解读：其卡片点击进入站内解读详情页 `/wechat/<slug>`（见上）。

## 验收侧重

**三维均衡覆盖**：内容质量、功能完整性、视觉/交互体验同等重要。

| 维度 | L1 影响 | L2 影响 |
|------|---------|---------|
| **内容质量 + 信息时效** | 精选页描述详细覆盖评分、推荐理由、信源质量 | 验证条件包含内容语义准确性、每日有新内容、中文质量 |
| **功能完整性 + 流程可用** | 所有页面和交互功能均完整描述 | 每个筛选器/搜索/分页/跳转都有具体判定条件 |
| **视觉 + 交互体验** | 桌面和移动端布局均纳入描述 | 排版、响应式、加载状态、空状态都有可观测条件 |

**设备范围**：桌面端和移动端同等验收。

**微信文章解读功能的侧重（与全站三维均衡不同，本轮对齐）**：**功能流程 + 视觉交互高优先**——列表→详情→分享流程、导航/分页/边界处理、暗色风格一致性与响应式是本轮验收重点，L2 在这些维度给具体判定条件。**解读内容质量本轮不验**：结构化解读是否忠实原文/有用、"值得读"判定是否合理，视为 summarizer 产出，L2 只验"渲染正确、中文可读、无外露转义字符"，不做内容质量/判定合理性的 human judgment（留待后续轮次，见 ux-issues.md 引导项）。

## 用户视角验证条件（L2）

### 精选页

**HP-1：精选内容加载与展示**
- 打开 `https://aiplanet.live`，页面加载完成
- `/` 首屏内容通过 SSR preload 直出；HTML 到达时已包含 `.item-row`，首屏展示不依赖初始 `/api/v1/*` fetch，不出现可感知 loading spinner
- 首屏直出的卡片数与客户端首批相同：从首次绘制到页面稳定，卡片数不发生变化，且这段时间内**不产生可归因于首批交接的布局位移**（以浏览器 `layout-shift` 观测、排除用户输入引发的位移，累计值应为 0）
- same-host provisional 浏览器探针中，首页首张 `.item-row` 可读延迟 P75 ≤2s、P95 ≤3s；该结果不作为 East Asia 或其他区域 SLO
- 首屏展示多条最新精选卡片（正常日 ≥10 条）；精选页是所有历史精选条目的累积归档，向下滚动持续加载（见 HP-8）
- 每张卡片可见：中文标题、摘要、信源名称和图标、推荐理由、分数标签、发布时间
- `>960px` 另可见"精选"标记；`≤960px` 行首只有时间 + 信源（左）与分数（右），不显示"精选"标记与收藏按钮
- **首页任何档位都不显示话题标签**（标签见 TL-5）
- 分数标签颜色与数值匹配（≥80 高亮、65-79 中等、<65 低调）
- 内容按日期从新到旧排列

**HP-2：精选内容质量**（human judgment required）
- 标题和摘要为可读的中文，不是乱码或纯英文原文
- 推荐理由能清晰说明为什么这条内容值得关注——pass 示例："首次系统分析 AI 基础设施扫描行为，为安全团队提供攻击面情报"；fail 示例："这是一条关于 AI 的重要新闻"
- 分数分布合理：高分内容（≥80）应对应重大事件或高信息密度内容，不应出现明显低质内容获得高分

**HP-3：分类筛选**

- 再次点击或选择"全部"恢复全部内容
- 筛选后列表不为空时，所有卡片的话题与选中分类相关
- 访问 `/?category=<无效 slug>` 时静默回退到"全部"，不报错；客户端会把地址栏中的无效 `category` 参数剥除并改写为公开根路径或仅保留其他有效参数

**HP-4：搜索**

- 搜索无结果时显示友好的空状态提示

**HP-7：媒体资产**
- 列表卡片只展示 **X 推文自带的媒体**；从 RSS 正文抓取的配图一律不展示（[ADR-054](../adr/054-stop-rendering-article-images-in-list-cards.md)）。这条区分是有意的：推文的图就是推文本身的内容，而正文图多为论文首页或网页截图，缩到卡片尺寸后读不出内容却占满首屏。`/wechat` 详情页的配图不受此限
- 一条推文带多张图时全部展示，顺序与推文一致；视频与 GIF 展示其静态封面（X 的接口不返回可直接播放的地址）
- 点击图片在新标签页打开大图（查看原图；进入原文走标题链接）
- 无媒体的卡片正常展示，不出现空白区域；**媒体全部加载失败时卡片高度与无媒体卡片一致**——不留下容器占位的空隙
- 卡片头像与推文媒体使用 lazy loading；首屏外图片不应在初次 HTML 加载/首屏渲染阶段下载完成，也不应阻塞 `.item-row` 文本可读性
- 图片加载失败时，文字内容、标题链接、标签和时间仍可读可点；图片失败不应导致整张卡片空白或布局崩坏
- 媒体经同源 `/img` 取回，不直连外部图床。出口代理不可达时，本条退化为「所有 X 卡片无媒体」——**这仍须满足上面无媒体与失败降级两条**，即页面除了少了图之外与正常状态无差别（[ADR-057](../adr/057-fetch-x-tweet-media-through-a-singapore-egress-proxy.md)）

**HP-8：无限滚动（累积归档）**
- 精选页是累积归档：汇总**所有曾被选入精选的不同条目**（跨历次 curation run 去重，每条只出现一次），按发布时间从新到旧展示——总条目数远多于单轮 top-40（当前约 1,700+ 条）
- 滚到底自动追加下一批（每批约 40 条），无数字页码控件
- 追加过程中条目数单调递增且**任何时刻不重复**（按唯一条目 key 在追加时去重——采集管线并发写入使 offset 分页可能跨页重发边界条目，去重保证它们不产生重复卡片）
- 数据集稳定（滚动期间无采集写入）时，滚到 terminal 后页面上的唯一条目数**精确等于 API 报告总量**——无限滚动不牺牲归档完整性
- 滚动期间发生采集写入时：无重复仍恒成立；期间新增的条目不保证并入本次滚动（刷新后可见），总量以刷新后的新代际收敛
- 分类筛选 / 搜索生效时，总量随筛选结果变化；快速连续切换筛选时，最终列表只属于最后一次选择（请求代际校验防竞态）
- 日期分组可折叠，追加加载的新批次继承已有折叠态

**HP-9：日期前缀**
- 页头副标题的日期前缀取**当前列表中最新一条内容**的发布日期（Asia/Shanghai，中文长日期），不是日历当天
- 初始加载、分类 / 搜索变化及刷新后同步更新；空结果时日期前缀消失

**HP-10：热点模块**
- 严格显示 `GET /api/v1/hot?limit=2` 返回的前 2 条（响应不足 2 条时与实际数一致），排序、key 与热度值与 API 一致
- 标题：桌面「当前热点」，≤960px「今日热点」
- 右上「完整榜单 →」精确跳转 `/hot`

### 日报页

**DY-1：日报加载与结构**
- 打开 `/daily`，展示最近有数据的日期的精选汇总，页面为**浅色**、使用全站设计 token
- 报头：`VOL.<YYYY.MM.DD> · <N> STORIES · AI RADAR DAILY` + 主标题 `AI RADAR 日报` + 中文长日期。`VOL` 取当前有效日报日期，`N` **等于实际渲染的正文条目数**（动态，不是固定值）
- 「今日看点」摘要卡：分类编号 + 标题 + 每类条数 + `N 篇报道 · 约 M 分钟`；`N` 等于实际正文条数，各类计数之和等于 `N`
- 阅读时长 `M = max(1, ceil(C / 300))`，`C` 只计正文摘要的可见中文字符（CJK Unified Ideographs），排除标题、导航、元数据与章节标题
- 章节头形态：`01 行业动态 INDUSTRY … 1 篇`
- 内容按分类分组展示
- 正文末尾有四项数据概览（今日事件 / 一手报道 / 新模型 / 信源）；桌面为一行四格，`≤960px` 为 2×2
- 四个数值各自可被独立重算核对：今日事件等于正文实际条目数（也等于报头 `N STORIES` 的 `N`）；一手报道等于该期中非推文类且信源等级为 T1 的条目数；新模型等于该期中属「模型发布」分类的条目数；信源等于该期去重信源数
- 某期无内容时该概览整体不出现，不显示占位的 0
- 正文摘要中的行内代码呈现为等宽字体的浅底圆角块，不是普通正文样式

**DY-2：日期导航与归档**
- 归档侧栏按**月份分组、可折叠**；月份行显示该月期数，展开后列出该月每期；底部有「全部日报 →」
- 显示的月份数、各月期数与日期集合，与可用日报全集一致（不截断）
- 点击某个日期，主内容区切换到该日期的精选内容；← → 箭头可在相邻日期间导航；最新日期的"后一日"按钮隐藏
- 导航到任一**过去**的有精选内容的日期（侧栏列出的日期、或直接访问 `/daily/{date}`），主内容区展示该日的精选条目而非空报告——日报按日期汇总跨所有 curation run、发布于该日的精选条目（与精选页同口径），不限于最新一轮 run

**DY-4：日期边界行为**
- **非法、不可解析或晚于今天**的日期（如 `/daily/9999-99-99`、`/daily/<未来日期>`）：回退到最近一期并改写 URL，在报头附近显示**一行非警示色**的低强调内联状态文字（`role="status"`，包含实际回退日期）。不再使用醒目警示横幅
- **合法日期格式但当天无内容**（如 `/daily/2000-01-01`）：**不回退**、URL 不改写，主内容区显示明确空态文案，不是白屏

**DY-3：日报内容一致性**
- 日报页某日期的内容条目应与该日被选入精选的条目一致——无论该日期是今天还是过去某天（这些条目即精选归档中该日期的部分，过去日期同样应有内容、不为空）
- 分类分组正确（同分类的条目在同一区块内）

### 响应式与视觉

**断点**：`640px` / `960px` / `1200px`，另有 `(min-width:641px) and (max-width:960px)` 与 `(hover:none),(max-width:960px)`。`≤960px` 是桌面布局与移动布局的分界。

**RS-1：桌面端布局（>960px）**
- 侧边栏导航可见，内容区充分利用宽度；底部 tab 栏不显示
- 侧栏「内容」分组含热点榜，「更多」分组含更新日志，当前页高亮
- 卡片排版整齐，文字可读
- 日期分组头显示绝对日期，同级 meta 显示星期与条数
- 日期分组头里的日期，其**文字右边界与该组下方每一条时间戳的文字右边界对齐**（差值 ≤1px）。这一条要量文字本身的位置，不是量元素盒
- 同一日期分组内有**一条连续竖线**穿过该组全部条目的圆点，条目之间不断开；线的水平位置与圆点圆心重合
- 日期分组折叠后，该竖线不残留在空处
- 条目被收藏后其圆点转为琥珀色；取消收藏后恢复；刷新后与收藏状态一致
- 内容区宽度随视口增长而增长，不在某个宽度后固定不动（1440 视口下正文区明显宽于 1160px）

**RS-2：移动端布局（≤960px）**
- 侧边栏**整体替换为底部 tab 栏**（高 54px，恰好 4 项：精选 `/`、全部 `/all`、日报 `/daily`、更多 `/more`），当前页高亮。**没有**汉堡菜单或抽屉
- **顶部紧凑条（logo + 右侧日期，高 45px，随内容滚动、不吸顶）只在首页出现**；其余页面不显示品牌 + 日期条，而是使用各自的页面标题头。主导航由底部 tab 栏承担，不受影响
- 页头改为紧凑 section 标题，不再渲染占据近半屏的完整页头
- 首页分类筛选为可横向滚动的单行药丸 chip，搜索折叠为固定放大镜并跳 `/all#search`
- **`/all` 不同**：保留可直接输入的完整搜索表单（来源为下拉、分类为单行 tab），不退化成放大镜
- 卡片去边框全出血，条目间用发丝线分隔；日期分组头为浅灰吸顶条
- 推荐理由渲染为浅灰底块
- 日期分组头分**两段**呈现（主段更大更重、次段更小更轻）：今天 / 昨天时主段为相对日名、次段为绝对日期与星期；其他日期主段为绝对日期、次段只有星期（以 Asia/Shanghai 判日界）
- **日期分组头在该档不提供折叠控件**（桌面档提供）。不留隐藏但可键盘聚焦的折叠按钮
- **行首信息密度向紧凑收敛**：只有「时间 + 信源」在左、分数在同一行右端；不显示「精选」标记、收藏按钮与话题标签（三者在桌面档全部保留）。信源名不与分数重叠，常规长度的信源名完整显示（超长名称仍允许省略号截断）
- 推荐理由**完整显示、不截断为固定行数**
- 可点击元素满足触控目标：一般 ≥44px，紧凑控件（chip）≥36px
- 内容区单列布局，文字大小可读，不需要横向滚动
- 交互功能在移动端同样可用：筛选 / 搜索 / 无限滚动 / 跳转，以及经 `/more → 收藏` 查看与管理已收藏内容
- **收藏的新增入口只在桌面档（>960px）**。≤960px 可查看和管理既有收藏，但不能从列表新增——这是与参考站一致的形态取舍，收藏数据与收藏页本身不受影响
- 首页有顶部紧凑条且**滚动时随内容离开视口**（不吸顶）；其余页面无品牌 + 日期条
- 390 档 `/more`、`/bookmarks`、`/about`、`/wechat` 顶部为页面标题头而非品牌 + 日期条，且这些页面的四项底部 tab 栏仍可见、可用
- 日期分组头呈两段：主段字号与字重明显大于次段
- 日期分组头**没有折叠控件**，也不存在不可见但可用键盘聚焦的折叠按钮
- 列表卡片行首不出现「精选」标记、收藏按钮与话题标签；分数出现在该行右端
- 推荐理由完整显示：其内容高度不被固定行数裁掉（可滚动内容高度等于可见高度）
- 正文区左右留白对称（差值 ≤2px）

**RS-5：主题三态**
- 侧栏底部三态切换（浅色 / 深色 / 跟随系统），localStorage 持久
- 当前档由一块**滑动选中底板**指示，切换时滑到对应档位（`prefers-reduced-motion` 下不做过渡动画）；刷新后位置与持久化的档位一致
- `data-theme` 与 `data-theme-mode` 随选择变化，`<meta name="theme-color">` 与实际主题一致
- head 内联脚本在首屏 app init 前即设好上述三项，无主题闪烁

**RS-3：加载状态**
- `/` 和 `/all` 首屏通过 SSR preload 渲染；HTML 到达时 `.item-row` 已可见，不依赖初始 `/api/v1/*` fetch，不显示可感知 loading spinner
- 筛选、搜索、翻页等后续数据请求期间可以显示加载指示
- 后续请求加载完成后指示消失，内容正常显示

**RS-4：空状态**
- 搜索无结果时显示友好提示（如"没有匹配条目"）
- 分类或信源类型筛选无匹配结果时显示友好提示
- 某日期无精选内容时显示合理提示
- 精选页数据异常导致条目极少（<5 条）时，页面仍正常渲染不报错

### 数据时效性

**FH-1：每日更新**
- 精选页有当天（或前一天）的新内容
- 不应出现连续多天无新内容的情况

**FH-2：信源覆盖**
- 精选和时间线中能看到来自不同信源的内容（不是只有一两个源）

## 范围与约束

### 在范围内
- `https://aiplanet.live` 上的所有公开页面：精选 `/`、时间线 `/all`、热点榜 `/hot`、日报 `/daily`、收藏 `/bookmarks`、关于 `/about`、更新日志 `/changelog`、更多 `/more`、微信文章解读列表 `/wechat` 与解读详情 `/wechat/<slug>`
  - 其中 `/more` **只在 ≤960px 有导航入口**（底部 tab 栏第 4 项），桌面无入口；`/hot` 桌面从侧栏进入、移动端从首页「完整榜单 →」进入
- 桌面端和移动端浏览器体验，含 125% / 150% / 200% 缩放
- 所有用户可见的交互功能

### 不在范围内
- 管理后台或数据管道（不是用户可见的部分）
- API 直接调用的验收（API 是前端的支撑，通过前端行为间接验证）
- SEO，或外部 benchmark 工具 / 第三方地域性能测试；首页与微信的用户可感知旅程延迟已纳入 same-host provisional 性能监控
- 浏览器兼容性（仅需验证主流浏览器 Chrome/Safari）

### 隐式假设
- 产品持续有新内容更新
- 内容的中文标题、摘要、推荐理由能正常展示
- 网站 `https://aiplanet.live` 可正常访问

## Defaulted Decisions

| 决策 | 默认值 | 理由 |
|------|--------|------|
| 分数标签颜色阈值 | ≥80 高亮、65-79 中等、<65 低调 | 基于当前产品展示的实际阈值 |
| 精选页内容口径 | 所有曾被精选的不同条目（跨历次 run 去重），按发布时间倒序分页 | 用户对齐：精选是 AI 优选的 best-of **累积归档**，非仅最新一轮 top-40；排序与全站 feed 一致 |
| 精选页"正常日"最少条数 | ≥10 条（首屏） | 精选页是累积归档；首屏展示最新精选，正常日 ≥10 条，10 为保守下限 |
| 每批条数 | 约 40 条（`/`、`/all`），`/wechat` 约 50 条 | 基于各页面的实际加载量 |
| `/`、`/all` 的浏览方式 | 无限滚动（滚到底追加），追加按唯一 key 去重；稳定数据集下 terminal 唯一条目数 = API total，采集并发写入时无重复、刷新后收敛 | 与参考站对齐；完整性由稳定态 terminal 总量断言保证，不靠页码 |
| `/all` 搜索态 | 仍用 page 分页 | timeline API 搜索时忽略 cursor，无法续取；既有实现约束下的有意取舍 |
| `/wechat` 列表 | 仍用数字页码分页 | 本轮未改动微信列表的浏览方式 |
| 移动断点与导航 | ≤960px 切底部 4 项 tab 栏，无汉堡抽屉 | 与参考站对齐；「更多」跳独立 `/more` 页而非抽屉，经参考站 DOM 核实 |
| 日报阅读时长 | `M = max(1, ceil(C/300))`，`C` 只计正文摘要可见中文字符 | 本站自定的保守、整数、可审计契约；不声称与任何参考站算法一致 |
| 热点热度公式 | `heat = round(加权分×10 + 关联讨论数×5)`，窗口 48 小时 | 沿用既有 `/api/v1/hot` 排序逻辑，页面如实说明而非套用他站语义 |
| 浏览器范围 | Chrome + Safari | 覆盖桌面和移动端主流浏览器 |
| 信源池最少数量 | ≥20 条 | 当前约 41 个信源，20 为保守下限 |
| 微信文章解读内容质量验收 | 本轮 de-scoped（L2 只验渲染正确） | 用户对齐：功能流程 + 视觉交互优先，解读内容质量先不看 |
| 解读详情模块集合 | 随文章而变（核心 6 模块 + 部分文章额外模块如产品方向洞察） | 实测 summarizer 产出模块数不固定，不硬断言"恰好 6 个" |
| `/wechat` 每页条数 | 约 50 条 | 基于当前列表实际加载量 |
| 微信解读列表收录口径 | 进入"值得阅读列表"即收录（偏召回，可含"可跳过"等级文章） | 列表展示与详情可达性同口径；"收录"与每篇的推荐等级（必读/值得一看/可跳过）是两个独立信号 |
