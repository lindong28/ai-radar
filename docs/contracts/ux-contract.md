# AI Radar — UX Contract

> 验收规格文档。读者：用户（审完整性）+ test-ux agent（按此展开测试）。
> 不含实现细节、内部状态、待办事项。

---

## 产品概述

**产品形态**：公开只读 Web 应用，部署在 `https://aiplanet.live`

**使用者**：工程师（单人维护 + 公开浏览），日常用于 AI 领域信息消费——每天快速浏览精选内容掌握 AI 动态，需要时通过时间线和搜索深入某个方向。

**使用方式**：
- **日常浏览**（~5 分钟）：打开精选页，扫标题和推荐理由，点感兴趣的去原文
- **深度探索**（按需）：切到时间线页，用信源类型/分类/搜索筛选，逐页浏览
- **回顾查阅**（按需）：日报页按日期查看历史精选汇总

**核心价值**：从 40+ 个信源中自动筛选高价值 AI 资讯，通过评分 + 规则过滤实现"精度 ≫ 召回"——每天精选约 30-40 条（vs. 原始时间线数百条），降低信息噪音。

## 页面与功能

### 精选页（`/`，首页）

产品的核心入口，展示经过评分和规则过滤后的高价值内容。

**内容卡片包含**：
- 信源图标 + 信源名称
- 中文标题
- 中文摘要
- 推荐理由（解释为什么这条值得看）
- "精选"标记 + 分数标签（数字分数，颜色编码：≥80 高分、65-79 中等、<65 低调）
- 话题标签（最多 4 个受控词汇标签）
- 媒体资产（文章配图，可点击查看原图）
- 关联讨论（同一事件在其他信源的报道数量，悬停可查看信源列表）
- 发布时间
- 点击标题 → 在新标签页打开原文

**筛选功能**：
- 分类筛选：模型 / 产品 / 行业 / 论文 / 技巧（5 个分类）
- 搜索：全文搜索标题和摘要

### 时间线页（`/all`）

完整的按时间排列的内容流，用于深度浏览和探索。

**内容卡片**：与精选页类似——所有条目显示分数标签，被精选的条目额外显示"精选"标记和推荐理由。

**筛选功能**：
- 分类筛选：同精选页（5 个分类）
- 信源类型筛选：全部 / 一手信源（官方源）/ 资讯 / 推文（3+1 选项）
- 搜索：全文搜索
- 分页：翻页浏览（每页约 40 条）

### 日报页（`/daily`）

按日期组织的精选内容归档。

**页面结构**：
- 日期档案侧边栏：列出近期有数据的日期，可点击切换
- 日期导航：← 前一日 / 后一日 → 箭头按钮
- 主内容区：当天精选内容按分类分组展示
- 顶部 header：显示 VOL 编号（格式 `VOL.YYYY.MM.DD`）、故事数量、日期

### 关于页（`/about`）

产品信息和透明度展示。

**内容**：
- 产品定位说明
- 信源池表格：列出所有信源的标识、名称、等级（T1/T1.5/T2）、状态、类型；表格上方有搜索框可过滤信源
- 评分维度解释：5 维评分（相关性、信息密度、时效性、权威性、工程价值）及权重
- 设计原则
- 致谢（项目引用和相关链接）
- 维护者联系方式 / GitHub 链接

### 条目跳转（点击标题）

点击任何卡片标题，在新标签页直接打开原文链接。产品不提供独立的条目详情展示页。

## 验收侧重

**三维均衡覆盖**：内容质量、功能完整性、视觉/交互体验同等重要。

| 维度 | L1 影响 | L2 影响 |
|------|---------|---------|
| **内容质量 + 信息时效** | 精选页描述详细覆盖评分、推荐理由、信源质量 | 验证条件包含内容语义准确性、每日有新内容、中文质量 |
| **功能完整性 + 流程可用** | 所有页面和交互功能均完整描述 | 每个筛选器/搜索/分页/跳转都有具体判定条件 |
| **视觉 + 交互体验** | 桌面和移动端布局均纳入描述 | 排版、响应式、加载状态、空状态都有可观测条件 |

**设备范围**：桌面端和移动端同等验收。

## 用户视角验证条件（L2）

### 精选页

**HP-1：精选内容加载与展示**
- 打开 `https://aiplanet.live`，页面加载完成
- 展示多条精选内容卡片（正常日 ≥10 条）
- 每张卡片可见：中文标题、摘要、信源名称和图标、推荐理由、"精选"标记、分数标签、话题标签、发布时间
- 分数标签颜色与数值匹配（≥80 高亮、65-79 中等、<65 低调）
- 内容按日期从新到旧排列

**HP-2：精选内容质量**（human judgment required）
- 标题和摘要为可读的中文，不是乱码或纯英文原文
- 推荐理由能清晰说明为什么这条内容值得关注——pass 示例："首次系统分析 AI 基础设施扫描行为，为安全团队提供攻击面情报"；fail 示例："这是一条关于 AI 的重要新闻"
- 话题标签与内容语义一致（例如关于模型发布的文章标签包含"模型"类标签）
- 分数分布合理：高分内容（≥80）应对应重大事件或高信息密度内容，不应出现明显低质内容获得高分

**HP-3：分类筛选**
- 点击任一分类标签（模型/产品/行业/论文/技巧），页面仅展示该分类下的内容
- 再次点击或选择"全部"恢复全部内容
- 筛选后列表不为空时，所有卡片的话题与选中分类相关

**HP-4：搜索**
- 输入关键词（如"Claude"）并搜索，结果列表中的内容与关键词相关
- 清空搜索恢复默认列表
- 搜索无结果时显示友好的空状态提示

**HP-5：点击跳转**
- 点击卡片标题 → 在新标签页打开原文链接
- 原文链接可访问（非 404）

**HP-6：关联讨论**
- 有关联讨论的卡片显示讨论数量
- 悬停讨论区域可查看关联的其他信源列表
- 无关联讨论的卡片不显示讨论区域

**HP-7：媒体资产**
- 有配图的卡片展示文章图片
- 图片可加载、不显示为占位符或破损图标
- 点击图片在新标签页打开原文链接（图片作为源文章的视觉入口）
- 无配图的卡片正常展示，不出现空白区域

### 时间线页

**TL-1：时间线加载与展示**
- 打开 `/all`，展示完整时间线内容
- 每页展示多条内容卡片（约 40 条）
- 所有条目显示分数标签
- 被精选的条目额外显示"精选"标记和推荐理由
- 内容按时间从新到旧排列

**TL-2：信源类型筛选**
- 点击"一手信源"，仅展示官方源的内容
- 点击"资讯"，仅展示资讯类源的内容
- 点击"推文"，仅展示 X/Twitter 来源的内容
- 各筛选结果内的信源类型一致

**TL-3：分类筛选 + 搜索**
- 分类筛选行为同精选页（HP-3）
- 搜索行为同精选页（HP-4）
- 分类和信源类型可以组合使用

**TL-4：分页**
- 页面底部有翻页控件
- 点击下一页，加载新的内容，不与上一页重复
- 翻页后可返回上一页

### 日报页

**DY-1：日报加载与结构**
- 打开 `/daily`，展示最近有数据的日期的精选汇总
- 页面顶部显示 VOL 编号（格式 `VOL.YYYY.MM.DD`）、故事数量、日期
- 内容按分类分组展示

**DY-2：日期导航**
- 侧边栏显示近期有数据的日期列表
- 点击某个日期，主内容区切换到该日期的精选内容
- ← → 箭头可在相邻日期间导航
- 最新日期的"后一日"按钮隐藏（不可见）

**DY-3：日报内容一致性**
- 日报页当天的内容条目应与精选页展示的条目一致（同一天的相同精选结果）
- 分类分组正确（同分类的条目在同一区块内）

### 关于页

**AB-1：信源池展示**
- 打开 `/about`，展示信源池表格
- 表格包含信源标识、名称、等级、状态、类型信息
- 信源数量 ≥20 条（产品正常运行的基本保障）
- 等级分布可见（T1/T1.5/T2）

**AB-2：信源搜索**
- 信源表格上方的搜索框可输入关键词
- 输入后表格内容被过滤，仅显示匹配的信源

**AB-3：评分解释**（human judgment required）
- 展示 5 个评分维度（relevance、density、recency、authority、engineering）及其权重说明
- 维度名称和权重数值清晰可读

**AB-4：链接可达**
- 页面上的 GitHub 链接、致谢中的外部链接等可正常访问

### 响应式与视觉

**RS-1：桌面端布局**
- 在桌面浏览器（≥1024px）下页面正常渲染
- 侧边栏导航可见，内容区充分利用宽度
- 卡片排版整齐，文字可读
- 字体加载正常（Serif 标题 + Sans 正文 + Mono 技术细节）

**RS-2：移动端布局**
- 在移动端（~390px 宽度）下页面正常渲染
- 导航变为汉堡菜单，可点击展开
- 内容区单列布局，卡片自适应宽度
- 文字大小可读，不需要横向滚动
- 所有交互功能（筛选/搜索/分页/跳转）在移动端同样可用

**RS-3：加载状态**
- 页面加载/数据请求期间显示加载指示
- 加载完成后指示消失，内容正常显示

**RS-4：空状态**
- 搜索无结果时显示友好提示（如"没有匹配条目"）
- 分类或信源类型筛选无匹配结果时显示友好提示
- 某日期无精选内容时显示合理提示
- 精选页数据异常导致条目极少（<5 条）时，页面仍正常渲染不报错

### 数据时效性

**FH-1：每日更新**
- 精选页有当天（或前一天）的新内容
- 不应出现连续多天无新内容的情况

**FH-2：信源覆盖**
- 精选和时间线中能看到来自不同信源的内容（不是只有一两个源）
- 信源种类覆盖：官方源、资讯、推文等

## 范围与约束

### 在范围内
- `https://aiplanet.live` 上的所有公开页面（精选、时间线、日报、关于）
- 桌面端和移动端浏览器体验
- 所有用户可见的交互功能

### 不在范围内
- 管理后台或数据管道（不是用户可见的部分）
- API 直接调用的验收（API 是前端的支撑，通过前端行为间接验证）
- SEO 或性能基准测试
- 浏览器兼容性（仅需验证主流浏览器 Chrome/Safari）

### 隐式假设
- 产品持续有新内容更新
- 内容的中文标题、摘要、推荐理由能正常展示
- 网站 `https://aiplanet.live` 可正常访问

## Defaulted Decisions

| 决策 | 默认值 | 理由 |
|------|--------|------|
| 分数标签颜色阈值 | ≥80 高亮、65-79 中等、<65 低调 | 基于当前产品展示的实际阈值 |
| 精选页"正常日"最少条数 | ≥10 条 | 实际观测到当天约 40 条精选，10 条为保守下限 |
| 翻页每页条数 | 约 40 条 | 基于当前页面的实际加载量 |
| 浏览器范围 | Chrome + Safari | 覆盖桌面和移动端主流浏览器 |
| 信源池最少数量 | ≥20 条 | 当前约 41 个信源，20 为保守下限 |
