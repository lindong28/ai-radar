# 测量与仪器 经验

> Append-only. 关于"读数本身可不可信"的坑点——测试、探针、记录器、eval 指标共用同一套失败形态。

## 仪器失明：读数在"结论为真"和"结论为假"时取值相同

一次任务里连续踩中 **7 次**同一形态的失败（第 7 条由一名评审者报出、我复核）。它们分布在测试、后台记录器、eval 指标三类完全不同的东西上，但失败方式是同一个：

> **仪器在"被测的事发生了"和"没发生"两种情况下给出同一个读数**，于是"全绿"既可能是"没问题"，也可能是"我瞎了"，而这两者在观察面上不可区分。

它比"仪器报错"危险得多——报错会被处置，同形只会被采信。六次里没有一次是靠"多看一眼"发现的。

### 七个实例

| # | 仪器 | 假读数 | 真相 | 谁发现的 |
|---|---|---|---|---|
| 1 | 突变检验 | 突变"存活" ⇒ 判定这里缺测试 | 等长替换被陈旧 `.pyc` 吃掉，跑的是突变前的字节码。详见 [dev-environment.md](./dev-environment.md) 同名条目 | 清缓存复验 |
| 2 | 「分批提交」的单元测试 | 绿 ⇒ 判定 commit 分批生效 | 用**写入的同一个连接**读回行数，而 sqlite 让连接看见自己未提交的写入；把 `commit` 移出循环后它照样绿 | 突变检验 |
| 3 | pipeline 阶段停滞探针 | 非零退出 ⇒ 判定生产被饿死 | 探针自己崩溃也是非零退出，与真停滞同形。会报告一次从未发生的饿死并睡满 8 小时 | 代码评审 |
| 4 | 饥饿记录器（后台采样） | 连续 111 个样本记 `0` ⇒ 判定饥饿已消失 | 我把探针 CLI 的 `score` 从位置参数改成 `--stage`，记录器仍传位置参数；`argparse` 报错、输出被 `sed` 吞成空、落盘为 `0` | 事后核对采样时间线 |
| 5 | 参考物自身一致性测量 | 4 对样本 0/4 分歧 ⇒ 判定参考物是纯噪声 | 两批数据字段名不同（`aihot_summary` vs `summary`），比的是"有值"与"空" | 内部一致性检查（见下） |
| 7 | eval 的**身份记录**（`prompt_sha256`） | 四个 run 哈希相同 ⇒ 判定「两个 arm 没差别、对照作废」 | `run.py` 的 `_PROMPT_FILES` 硬编码 prompt 路径，变体实现在别的模块里，身份记录看不见。详见 `docs/issues/aihot-fit-eval.md` ISSUE-FIT-34 | 核 `model_selection_env` |
| 6 | 「失败后是否恢复」的 SQL 判据 | 77 条里只有 7 条永久缺产出 ⇒ 判定"重试都成功了" | 谓词写的是"该 item 有没有**任何**一条成功 enrich"，于是**另一个 ruleset 版本下的陈旧成功**被读成本次恢复。按 `(item_id, ruleset_version)` 重算是 **77/77 全部未恢复** | 顺手打开一条样本的完整历史 |

### 它们共享的结构

每一个都是**仪器假定了一个耦合、但没有断言它**：

| # | 假定的耦合 | 它为什么会断 |
|---|---|---|
| 1 | 源文件改了 ⇒ 跑的是新字节码 | `.pyc` 按 mtime 秒 + 文件大小判失效，等长同秒改写不失效 |
| 2 | 读到行 ⇒ 行已提交 | 同一连接看得见自己未提交的写入 |
| 3 | 非零退出 ⇒ 被测对象异常 | 仪器自己也会非零退出 |
| 4 | 命令跑通 ⇒ 参数还是那几个 | 我自己改了被调方的签名 |
| 5 | 字段有值 ⇒ 两侧可比 | 两批数据的 schema 不同 |
| 6 | 有成功行 ⇒ 这次失败被补上了 | 成功行可以来自另一个版本/另一次运行 |
| 7 | prompt 文件的 hash ⇒ 跑的是哪个 prompt | 变体可以住在这个文件之外 |

**注意第 4 条：打瞎仪器的是我自己**，而且是在同一轮任务里。所以"这个仪器昨天是对的"不构成今天的证据——**改了被测系统的接口，就等于改了所有观察它的东西**，而观察者不在你的改动清单上。

### 能挡住它的三件事（按性价比排序）

1. **给每个仪器一个"测不出来"档。** 实例 3、4 的共同点是仪器只有两档（正常 / 异常），于是"我坏了"必须冒充其中一档。三值 + 三个退出码（`0`=无 / `1`=有 / `2`=未核实），消费方对 `2` 只记录、不据以行动。这一条最便宜，且能同时挡住 3 和 4。
2. **先问"这个读数在相反结论下会不同吗"，答不出就跑对照。** 报"通过"时跑**阳性**对照（已知有信号，看它报不报得出失败）；报"失败"时跑**阴性**对照。实例 1、2 都是被突变检验（即阳性对照）抓出来的。
3. **内部一致性检查——唯一抓住实例 5 的那件事。** 它不是对照，是拿这个读数去推一个**别处已有读数**的推论，看两者矛不矛盾：`σ_error ≈ σ_total` 会推出"参考物是纯噪声"，而同一语料上实测 `ρ≈0.6`，纯噪声目标做不到。矛盾即仪器可疑。适用于对照跑不动、或对照本身要用同一套坏掉的管线的场合。

### 两条容易漏的边界

- **顺带产出的读数最危险。** 六条里有四条不是为当前问题专门跑的，是手边正好有一个数就拿来用了。为别的问题设计的仪器，它的"正常"定义也是为别的问题定的。
- **"我没找到"≠"它不存在"。** 实例 6 的谓词跑通了、返回了一个具体数字（7），完全不像一次失败。**返回了数字的查询和返回了正确数字的查询长得一样。**

## 指标饱和：噪声底高于你要检出的效应，于是"没变化"与"没效果"同形

上一节讲的是**仪器在两种结论下读数相同**。这一节是它的近亲，但成因不同：仪器没坏、对照也做得对，只是**这个指标在你的样本量下的随机波动，比你要检出的差异还大**。失败形态一样——所有候选都读作"无显著改善"，而其中可能真有一个是对的。

2026-09-09 的实例。目标是让精选页的类别构成靠近参照产品，验收指标是逐日的构成总变差（TV）。连着四个候选（类别乘子、类别偏置、信源先验特征、权重重拟合）在这把尺子上全部读作噪声级，据此判了四次"不泛化"。后来才量它自己的噪声底：

| | 逐日构成 TV |
|---|---|
| 参照产品**自己**每天 vs 它自己的合并均值 | 0.269 |
| 从合并分布按当日条数重抽的**纯抽样噪声** | 0.253 |
| 我方逐日 | 0.262 |

**三者无法区分。** 单日精选只有 5–35 条，构成比例的抽样误差就吃掉了全部信号。那四次"不泛化"的判断里，至少有一次（类别偏置）在换成多窗口合并口径后重测，方向就变了。

**做法**：定验收指标之前，先算**这个指标在你的样本量下的噪声底**——最简单的办法是从合并分布按同样的 n 重抽几百次，看它自己能造出多大的读数。噪声底 ≥ 你要检出的效应，就换指标（合并窗口、换成 per-input 口径），别去解释那个读不出来的差。

**这条与"边际比例不能当拟合验收"是两件事，都要过**：那条说的是**指标类型**不对（占比这个量，一个完全不看输入的规则也能拿满分）；这条说的是**同一个指标在这个样本量上**没有分辨力。

## 跨标注器的指标自带一个地板，而它常常比你要测的差距还大

同一个量，两边由**不同的标注器**打标签时，读数里混着标注分歧。2026-09-09 实测：同一批 1182 条内容，我方分类器与参照产品的分类器逐条一致率 55.3%（多数类基线 35.2%），**光是标注分歧就造出 0.312 的构成总变差**——比当时在追的 0.213 的"差距"还大。换成同一版分类 prompt 重算后残差降到 **0.129**，但仍是地板：低于这个量级的构成差不可归因于选择行为。

**两条出路，按可得性取**：

1. **让两边用同一个标注器。** 参照产品自己发布分类时，把我方产物匹配到它的条目、用**它的**标签算两边——地板直接消失。代价是只覆盖得到匹配上的那部分，**那是一个有偏子集**（实测只覆盖我方页面的 30%），要么如实标注这个边界，要么把未匹配的部分补标。
2. **改用对标注器偏移免疫的量**：抬升系数（选中占比 / 流占比）在各自标注器内部计算，标注器的系统性偏移在分子分母里约掉。

**不要用混淆矩阵反解**去把一侧的标签折算到另一侧的标签空间。实测一次：矩阵接近奇异，反解给出的类别占比出现明显不可能的值（某类 1.1%，而该类的召回率是 83%、我方产出占比 15%），且没有任何自检会报错。**它是一次仪器失败，不是一个读数。**

## 占比对占比之前，先核两侧的截断深度

两个榜单的类别构成不同，可能与排序质量无关——**只要某个类别在排序上分布不均匀（几乎总是如此），榜单取多深就决定了它的占比**。

2026-09-09 实例。我方精选每天 40 条，参照产品每天十几条，一直在直接比两者的类别构成，并把"模型发布类少 18 个百分点"判成排序缺陷。同一批候选、同一套打分、同一套标签，只改「每天取几条」：

| 每天取 | 模型类占比 |
|---|---|
| 参照产品的当日条数（中位 ~13） | 29.2% |
| 40（我方版面） | 19.8% |
| 全部达标（1998 条） | 13.7% |
| 参照产品实际 | 30.2% |

**取到同一深度时两边基本相同。** 那个"缺口"是版面长度造成的：这一类的条目分数高、集中在最顶端，榜单越长越被稀释。据此改排序，改的是一个不存在的缺陷。

**做法**：比构成之前先答一句"两边各取了多深"。深度不同就要么对齐深度再比，要么把深度当作已知混淆写进结论。这条与上面两节同族——**都不是仪器坏了，是比较对象没对齐**。
