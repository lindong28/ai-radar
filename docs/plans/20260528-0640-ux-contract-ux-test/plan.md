# UX Contract 端到端测试

**UX Contract**: `docs/contracts/ux-contract.md`
**产品入口**: `https://your-domain.example`
**产品形态**: 公开只读 Web 应用（无需认证）
**测试工具**: agent-browser（Web 端到端浏览器交互）
**测试设备**: 桌面端（≥1024px）+ 移动端模拟（~390px）

---

## Test Steps

### 精选页（`/`）

**TS-001：精选内容加载与展示** ← HP-1
- 操作：agent-browser 打开 `https://your-domain.example`，等待页面加载完成
- 观测：
  1. 页面成功加载，无报错
  2. 精选卡片数量 ≥10 条
  3. 每张卡片可见元素检查：中文标题、摘要、信源名称+图标、推荐理由、"精选"标记、分数标签（数字）、话题标签、发布时间
  4. 分数标签颜色编码：≥80 高亮色、65-79 中等色、<65 低调色（取 3 张不同分段的卡片验证）
  5. 内容按日期从新到旧排列（对比相邻卡片的发布时间）
- Pass 判据：上述 5 项全部满足
- Fail 判据：任一项不满足
- L3 增强：检查网络请求（API 响应状态码 200、响应时间 <5s）；检查 console 无 JS error

**TS-002：精选内容质量** ← HP-2（human judgment required）
- 操作：从 TS-001 已加载的页面中，选取 5 张卡片进行内容质量审查
- 观测：
  1. 标题和摘要为可读中文（非乱码、非纯英文原文）
  2. 推荐理由具体且有信息量——pass 示例："首次系统分析 AI 基础设施扫描行为，为安全团队提供攻击面情报"；fail 示例："这是一条关于 AI 的重要新闻"
  3. 话题标签与内容语义一致（如模型发布文章标签含"模型"类标签）
  4. 分数分布合理：≥80 的内容应对应重大事件/高信息密度，不应出现明显低质内容获高分
- Pass 判据：5 张卡片中 ≥4 张各项满足；标记 human judgment required 的观测点（推荐理由质量、分数合理性）记录具体证据供 supervisor 裁决
- Fail 判据：≥2 张卡片出现乱码/纯英文，或 ≥3 张推荐理由空泛
- L3 增强：对高分条目（≥80）点击原文链接，验证摘要与原文大意一致（ux-test-patterns P10 来源可信度）

**TS-003：分类筛选** ← HP-3
- 操作：依次点击 5 个分类标签（模型/产品/行业/论文/技巧），每次观测结果
- 观测：
  1. 点击某分类后，页面仅展示该分类内容（卡片话题标签与分类相关）
  2. 筛选后列表不为空（至少有 1 条）
  3. 再次点击或选"全部"恢复全部内容，卡片数量回到筛选前
- Pass 判据：5 个分类各自筛选和恢复行为正确
- Fail 判据：任一分类筛选后内容不相关，或恢复失败
- L3 增强：检查 URL 参数是否与当前筛选状态一致（ux-test-patterns P3 深链接一致性）

**TS-004：搜索** ← HP-4
- 操作：
  1. 搜索 "Claude"，观测结果
  2. 清空搜索，观测恢复
  3. 搜索不存在的关键词（如 "zzznotexist123"），观测空状态
- 观测：
  1. 搜索 "Claude" 后结果与关键词相关（标题或摘要含 Claude 或相关内容）
  2. 清空搜索后恢复默认列表
  3. 无结果时显示友好空状态提示（非空白、非报错）
- Pass 判据：3 项操作行为均正确
- Fail 判据：搜索结果不相关，或空状态无提示

**TS-005：点击跳转** ← HP-5
- 操作：点击 3 张不同卡片的标题
- 观测：
  1. 每次点击在新标签页打开原文链接（target="_blank" 行为）
  2. 原文链接可访问（非 404、非空白页）
- Pass 判据：3 张卡片跳转均正确
- Fail 判据：未在新标签页打开，或原文链接不可访问
- L3 增强：检查原文链接 HTTP 状态码（curl -sI 验证非 4xx/5xx）

**TS-006：关联讨论** ← HP-6
- 操作：找到一张有关联讨论标记的卡片，悬停讨论区域
- 观测：
  1. 有关联讨论的卡片显示讨论数量（数字可见）
  2. 悬停后弹出关联信源列表（至少 1 个信源）
  3. 无关联讨论的卡片不显示讨论区域（对比验证）
- Pass 判据：讨论展示和悬停行为正确
- Fail 判据：讨论区域缺失、悬停无效、或无讨论的卡片错误显示讨论

**TS-007：媒体资产** ← HP-7
- 操作：找到有配图的卡片和无配图的卡片各 1 张
- 观测：
  1. 有配图卡片的图片已加载（非占位符、非 broken icon）
  2. 点击图片可查看原图（放大显示）
  3. 无配图卡片正常展示，无空白区域或布局错乱
- Pass 判据：图片加载、点击查看、无配图布局均正确
- Fail 判据：图片 broken、点击无反应、或无配图时布局异常

### 时间线页（`/all`）

**TS-008：时间线加载与展示** ← TL-1
- 操作：agent-browser 打开 `https://your-domain.example/all`，等待加载
- 观测：
  1. 页面成功加载，展示内容卡片
  2. 每页卡片数量约 40 条（±10 范围内合理）
  3. 所有条目显示分数标签
  4. 被精选的条目额外显示"精选"标记和推荐理由（与非精选条目有可见区分）
  5. 内容按时间从新到旧排列（ux-test-patterns P1 时间线排序语义）
- Pass 判据：5 项全部满足
- Fail 判据：任一项不满足
- L3 增强：API 响应检查（状态码、响应时间）；console 无 JS error

**TS-009：信源类型筛选** ← TL-2
- 操作：依次点击"一手信源""资讯""推文"筛选按钮
- 观测：
  1. "一手信源"：仅展示官方源内容，信源标识一致
  2. "资讯"：仅展示资讯类源内容
  3. "推文"：仅展示 X/Twitter 来源内容
  4. 各筛选结果内的信源类型一致（无混入）
- Pass 判据：3 种筛选各自结果正确
- Fail 判据：筛选结果混入其他类型信源
- L3 增强：比对 API 请求参数与 UI 筛选状态是否一致

**TS-010：分类筛选 + 搜索** ← TL-3
- 操作：
  1. 在时间线页点击一个分类（如"模型"），验证筛选
  2. 在已筛选状态下使用搜索
  3. 组合信源类型 + 分类（如"一手信源" + "产品"）
- 观测：
  1. 分类筛选行为同精选页
  2. 搜索行为同精选页
  3. 分类和信源类型组合后结果同时满足两个条件
- Pass 判据：各筛选和组合行为正确
- Fail 判据：组合筛选结果不满足条件之一

**TS-011：分页** ← TL-4
- 操作：滚动到页面底部，操作翻页控件
- 观测：
  1. 页面底部有翻页控件可见
  2. 点击下一页，加载新内容
  3. 新内容不与上一页重复（对比首条标题）
  4. 翻页后可返回上一页，内容与之前一致
- Pass 判据：翻页行为正确，无重复
- Fail 判据：无翻页控件、内容重复、或无法返回
- L3 增强：检查翻页前后 URL 参数变化；检查跨页边界排序连续性（ux-test-patterns P1）

### 日报页（`/daily`）

**TS-012：日报加载与结构** ← DY-1
- 操作：agent-browser 打开 `https://your-domain.example/daily`，等待加载
- 观测：
  1. 页面成功加载，展示最近有数据日期的精选汇总
  2. 顶部显示 VOL 编号（格式 `VOL.YYYY.MM.DD`）
  3. 顶部显示故事数量
  4. 顶部显示日期
  5. 内容按分类分组展示（可见分类标题）
- Pass 判据：5 项全部满足
- Fail 判据：任一项不满足

**TS-013：日期导航** ← DY-2
- 操作：
  1. 查看侧边栏日期列表
  2. 点击一个历史日期
  3. 使用 ← → 箭头导航
  4. 检查最新日期的"后一日"按钮状态
- 观测：
  1. 侧边栏显示近期有数据的日期列表（≥3 个日期）
  2. 点击历史日期后主内容区切换到该日期内容（VOL 编号变化）
  3. ← → 箭头可在相邻日期间导航
  4. 最新日期的"后一日"按钮隐藏或不可见
- Pass 判据：4 项全部满足
- Fail 判据：日期切换不生效、箭头导航失败、或最新日期仍显示后一日按钮

**TS-014：日报内容一致性** ← DY-3
- 操作：对比日报页当天内容与精选页当天内容
- 观测：
  1. 日报页当天的条目与精选页展示的当天条目一致（标题匹配）
  2. 分类分组正确（同分类条目在同一区块）
- Pass 判据：内容一致且分组正确
- Fail 判据：条目不一致或分组错误
- L3 增强：API 层面验证——对比 daily API 和 curated API 同日期的返回数据条目 ID

### 关于页（`/about`）

**TS-015：信源池展示** ← AB-1
- 操作：agent-browser 打开 `https://your-domain.example/about`，滚动到信源池表格
- 观测：
  1. 信源池表格可见
  2. 表格包含列：信源标识、名称、等级、状态、类型
  3. 信源数量 ≥20 条
  4. 等级分布可见（存在 T1、T1.5、T2 等不同等级）
- Pass 判据：4 项全部满足
- Fail 判据：表格缺列、信源 <20 条、或等级无分布

**TS-016：信源搜索** ← AB-2
- 操作：在信源表格上方搜索框输入关键词（如 "OpenAI"）
- 观测：
  1. 输入后表格被过滤，仅显示匹配信源
  2. 清空后恢复全部信源
- Pass 判据：搜索过滤和恢复正确
- Fail 判据：搜索无过滤效果或恢复失败

**TS-017：评分解释** ← AB-3（human judgment required）
- 操作：在关于页找到评分维度解释区域
- 观测：
  1. 展示 5 个评分维度：relevance、density、recency、authority、engineering
  2. 每个维度有权重说明
  3. 维度名称和权重数值清晰可读
- Pass 判据：5 维度均展示且可读
- Fail 判据：维度缺失或权重不可读

**TS-018：链接可达** ← AB-4
- 操作：找到页面上的 GitHub 链接和致谢中的外部链接
- 观测：
  1. GitHub 链接可点击且指向有效仓库
  2. 致谢中的外部链接可正常访问（非 404）
- Pass 判据：链接均可达
- Fail 判据：存在死链
- L3 增强：curl 验证所有外部链接的 HTTP 状态码

### 响应式与视觉

**TS-019：桌面端布局** ← RS-1
- 操作：在桌面浏览器（≥1024px）下依次访问 4 个页面
- 观测：
  1. 各页面正常渲染，无明显布局错乱
  2. 侧边栏导航可见
  3. 内容区充分利用宽度
  4. 卡片排版整齐，文字可读
  5. 字体加载正常（Serif 标题 + Sans 正文 + Mono 技术细节可区分）
- Pass 判据：5 项全部满足
- Fail 判据：布局错乱、导航不可见、或字体加载失败

**TS-020：移动端布局** ← RS-2
- 操作：设置浏览器视口为 ~390px 宽度，依次访问 4 个页面
- 观测：
  1. 各页面正常渲染
  2. 导航变为汉堡菜单，可点击展开
  3. 内容区单列布局，卡片自适应宽度
  4. 文字大小可读，不需横向滚动
  5. 筛选/搜索/分页/跳转在移动端均可用
- Pass 判据：5 项全部满足
- Fail 判据：横向滚动、控件不可用、或布局崩坏
- L3 增强：ux-test-patterns P7 窄屏扫读路径检查；P4 视觉隐藏元素 tab order 检查

**TS-021：加载状态** ← RS-3
- 操作：刷新页面并观察加载过程（可通过 network throttling 放慢）
- 观测：
  1. 数据请求期间显示加载指示（spinner/skeleton/进度条）
  2. 加载完成后指示消失，内容正常显示
- Pass 判据：加载指示可见且加载后消失
- Fail 判据：无加载指示或加载完成后残留
- L3 增强：ux-test-patterns P6 三种状态可区分检查

**TS-022：空状态** ← RS-4
- 操作：
  1. 搜索无结果关键词
  2. 组合筛选到无匹配结果
  3. 检查精选页异常少条目（<5 条）的行为
- 观测：
  1. 搜索无结果时显示友好提示（"没有匹配条目"或类似）
  2. 筛选无匹配时显示友好提示
  3. 条目极少时页面仍正常渲染不报错
- Pass 判据：各空状态均有友好提示且不报错
- Fail 判据：空白无提示或 JS 报错
- L3 增强：ux-test-patterns P6 空结果与错误状态区分

### 数据时效性

**TS-023：每日更新** ← FH-1
- 操作：检查精选页最新内容的发布时间
- 观测：
  1. 精选页有当天或前一天的新内容
  2. 不存在连续 3 天以上无新内容的情况
- Pass 判据：有近日新内容
- Fail 判据：最新内容超过 2 天前
- L3 增强：ux-test-patterns P8 内容新鲜度检查；API 层面验证最新条目 created_at

**TS-024：信源覆盖** ← FH-2
- 操作：浏览精选页和时间线页，统计可见信源
- 观测：
  1. 内容来自多个不同信源（≥5 个不同信源）
  2. 信源种类覆盖：至少包含官方源、资讯、推文中的 2 类
- Pass 判据：信源多样且类型有覆盖
- Fail 判据：只有 1-2 个信源或只有单一类型
